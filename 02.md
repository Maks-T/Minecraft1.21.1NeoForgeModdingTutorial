## 1. Теория: базовые классы игры и правила идентификаторов

### Классы с «S» и без «S» на конце
В исходном коде Minecraft (`net.minecraft.world.item`):
* **Без окончания «s» (`Item`, `Block`, `CreativeModeTab`):** базовые классы, определяющие поведение, свойства (максимальный размер стака, прочность, редкость и т. д.).
* **С окончанием «s» (`Items`, `Blocks`, `CreativeModeTabs`):** классы реестров Minecraft, где статически зарегистрированы все ванильные предметы/блоки.

### Идентификаторы (`ResourceLocation` / `Identifier`)
Каждый объект игры имеет уникальный адрес формата `namespace:path`:
* **Namespace (пространство имен):** обычно это ваш `MOD_ID` (по умолчанию у ванили — `minecraft`).
* **Path (путь/название):** имя объекта или путь к нему (например, `ice_ether` или `material/cardboard`).

#### Правила синтаксиса:
* Разрешены **только строчные буквы** английского алфавита (`a-z`), цифры (`0-9`), нижние подчеркивания (`_`), точки (`.`) и косые черты (`/`).
* **Запрещены:** заглавные буквы, пробелы, спецсимволы (`!`, `?` и т. д.).
* Дефис (`-`) в `namespace` в NeoForge/Forge использовать крайне не рекомендуется — это вызовет краш игры при запуске.
* Символ слэша `/` позволяет создавать иерархию (папки внутри ресурсов).

## 2. Создание класса регистрации предметов (`ModItems`)

1. В пакете вашего мода создайте подпакет `item`.
2. Внутри пакета `item` создайте класс `ModItems.java`.

В NeoForge для регистрации используется улучшенный механизм `DeferredRegister.Items`:

```java
package com.besson.tutorial.item;

import com.besson.tutorial.TutorialMod;
import net.minecraft.world.item.Item;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredItem;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModItems {
    // Создаем реестр предметов для нашего мода
    public static final DeferredRegister.Items ITEMS = 
            DeferredRegister.createItems(TutorialMod.MOD_ID);

    // 1. Обычный предмет
    public static final DeferredItem<Item> ICE_ETHER = 
            ITEMS.register("ice_ether", () -> new Item(new Item.Properties()));

    // 2. Второй обычный предмет
    public static final DeferredItem<Item> RAW_ICE_ETHER = 
            ITEMS.register("raw_ice_ether", () -> new Item(new Item.Properties()));

    // 3. Предмет с иерархическим путем в имени (папка material)
    public static final DeferredItem<Item> CARDBOARD = 
            ITEMS.register("material/cardboard", () -> new Item(new Item.Properties()));

    // Метод регистрации шины событий
    public static void register(IEventBus eventBus) {
        ITEMS.register(eventBus);
    }
}
```

> **Примечание:** `DeferredItem<Item>` — это обертка NeoForge над зарегистрированным объектом. Сами свойства предметов задаются через `new Item.Properties()` (например, огонестойкость `.fireResistant()`, максимальный размер стака `.stacksTo(64)` и т. д.).

## 3. Подключение регистрации к главной шине мода

Откройте ваш главный класс мода (`TutorialMod.java`) и в конструкторе вызовите метод регистрации:

```java
public TutorialMod(IEventBus modEventBus) {
    // Регистрация реестра предметов на шине событий мода
    ModItems.register(modEventBus);

    // Слушатель добавления предметов в ванильные креативные вкладки
    modEventBus.addListener(this::addCreative);
}
```

Благодаря этому вызову все статические константы класса `ModItems` будут инициализированы и зарегистрированы при запуске мода.

## 4. Настройка ресурсов (Assets)

Все ресурсы располагаются по пути: `src/main/resources/assets/<mod_id>/`.

### 4.1. Локализация (`lang/en_us.json`)
Создайте или отредактируйте файл `assets/tutorial_mod/lang/en_us.json`:

```json
{
  "item.tutorial_mod.ice_ether": "Ice Ether",
  "item.tutorial_mod.raw_ice_ether": "Raw Ice Ether",
  "item.tutorial_mod.material.cardboard": "Cardboard"
}
```
*Обратите внимание:* если в идентификаторе предмета использовался слэш (`material/cardboard`), в языковом ключе он заменяется на точку: `item.<mod_id>.material.cardboard`.

---

### 4.2. Модели (`models/item/`)
Создайте структуру папок:
* `assets/tutorial_mod/models/item/ice_ether.json`
* `assets/tutorial_mod/models/item/raw_ice_ether.json`
* `assets/tutorial_mod/models/item/material/cardboard.json` *(в подпапке `material`)*

**Пример `ice_ether.json`:**
```json
{
  "parent": "item/generated",
  "textures": {
    "layer0": "tutorial_mod:item/ice_ether"
  }
}
```

**Пример `raw_ice_ether.json`:**
```json
{
  "parent": "item/generated",
  "textures": {
    "layer0": "tutorial_mod:item/raw_ice_ether"
  }
}
```

**Пример `material/cardboard.json`:**
```json
{
  "parent": "item/generated",
  "textures": {
    "layer0": "tutorial_mod:item/material/cardboard"
  }
}
```

---

### 4.3. Текстуры (`textures/item/`)
Поместите PNG-изображения (обычно 16x16 пикселей) в соответствующие папки:
* `assets/tutorial_mod/textures/item/ice_ether.png`
* `assets/tutorial_mod/textures/item/raw_ice_ether.png`
* `assets/tutorial_mod/textures/item/material/cardboard.png`

> **Зачем нужны подпапки (например, `material/`)?**  
> В крупных модах с сотнями предметов распределение файлов по категориям через слэш помогает поддерживать чистую структуру проекта и не смешивать всё в одной директории.

## 5. Добавление предметов в Creative Mode Tab

Чтобы предметы отображались во вкладках инвентаря творческого режима, используйте метод `addCreative` в главном классе мода:

```java
private void addCreative(BuildCreativeModeTabContentsEvent event) {
    // Проверяем, что заполняется ванильная вкладка "Ингредиенты" (Ingredients)
    if (event.getTabKey() == CreativeModeTabs.INGREDIENTS) {
        event.accept(ModItems.ICE_ETHER);
        event.accept(ModItems.RAW_ICE_ETHER);
        event.accept(ModItems.CARDBOARD);
    }
}
```

## 6. Совет по организации кода (Code Folding)

При написании большого количества регистраций удобно визуально группировать код с помощью директив IDE:

```java
// region INGREDIENTS
public static final DeferredItem<Item> ICE_ETHER = ITEMS.register(...);
public static final DeferredItem<Item> RAW_ICE_ETHER = ITEMS.register(...);
// endregion
```

IntelliJ IDEA позволяет сворачивать такие блоки (кнопка `[-]` на полях или сочетание `Ctrl + .`), делая файл более читаемым.

## 7. Тестирование в игре

1. В IntelliJ IDEA запустите конфигурацию **`Run Client`** (зеленая кнопка Play).
2. Обратите внимание на логи в консоли: убедитесь, что в них нет ошибок (`ERROR`) и предупреждений о неправильном формате `ResourceLocation`.
3. Создайте или откройте тестовый мир.
4. Откройте инвентарь творческого режима, перейдите во вкладку **«Ингредиенты» (Ingredients)** и прокрутите вниз:
    * Предметы должны корректно отображаться со своими текстурами (а не в виде черно-фиолетовых текстур отсутствия модели).
    * При наведении должно отображаться корректное название из языкового файла.
    * Выбросите предметы на землю клавишей `Q` и убедитесь, что 2D-модель корректно рендерится в мире.
