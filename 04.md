## 1. Теория: Блок в мире (`Block`) и Блок в руке (`BlockItem`)

В архитектуре Minecraft один и тот же блок существует в двух разных состояниях:
1. **Блок (`Block`):** физический объект, установленный в пространстве игрового мира (имеет коллизию, твердость, сопротивление взрывам, звук разрушения).
2. **Блок-предмет (`BlockItem`):** объект, который лежит у игрока в инвентаре, отображается на панели быстрого доступа или выброшен на землю в виде лута.

> ⚠️ **Критически важное правило:**  
> Если зарегистрировать `Block`, но **не зарегистрировать** для него `BlockItem`, блок нельзя будет взять в руки, выдать себе через вкладку или положить в инвентарь. Попытка добавить такой блок в Creative Tab без `BlockItem` приведет к **немедленному крашу игры**.

## 2. Свойства блоков (`BlockBehaviour.Properties`)

Поведение блоков задается через класс `BlockBehaviour.Properties`:
* `.strength(float destroyTime, float explosionResistance)` — задает время разрушения (твердость) и сопротивление взрыву (например, `3.0f, 3.0f`).
* `.requiresCorrectToolForDrops()` — требует подходящий инструмент (кирка, топор и т.д.) для выпадения дропа.
* `.sound(SoundType)` — звуки шагов, установки и разрушения (камень, дерево, металл).
* `.mapColor(MapColor)` — цвет отображения на карте.
* `BlockBehaviour.Properties.ofFullCopy(Blocks.STONE)` — позволяет быстро скопировать все свойства уже существующего ванильного блока.

## 3. Создание класса `ModBlocks` с авто-регистрацией `BlockItem`

Чтобы не писать регистрацию предмета вручную для каждого нового блока, создадим удобный вспомогательный метод.

1. В проекте создайте пакет `block`.
2. Создайте класс `ModBlocks.java`:

```java
package com.besson.tutorial.block;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.item.ModItems;
import net.minecraft.world.item.BlockItem;
import net.minecraft.world.item.Item;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.Blocks;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredBlock;
import net.neoforged.neoforge.registries.DeferredRegister;

import java.util.function.Supplier;

public class ModBlocks {
    // 1. Создаем реестр блоков
    public static final DeferredRegister.Blocks BLOCKS = 
            DeferredRegister.createBlocks(TutorialMod.MOD_ID);

    // ================= РЕГИСТРАЦИЯ БЛОКОВ =================

    // 1. Блок ледяного эфира (ручная настройка свойств)
    public static final DeferredBlock<Block> ICE_ETHER_BLOCK = registerBlock(
            "ice_ether_block",
            () -> new Block(BlockBehaviour.Properties.of()
                    .strength(3.0f, 3.0f)
                    .sound(SoundType.AMETHYST)
                    .requiresCorrectToolForDrops())
    );

    // 2. Блок сырого ледяного эфира
    public static final DeferredBlock<Block> RAW_ICE_ETHER_BLOCK = registerBlock(
            "raw_ice_ether_block",
            () -> new Block(BlockBehaviour.Properties.of()
                    .strength(4.0f, 4.0f)
                    .sound(SoundType.STONE)
                    .requiresCorrectToolForDrops())
    );

    // 3. Руда ледяного эфира (свойства скопированы с ванильного камня)
    public static final DeferredBlock<Block> ICE_ETHER_ORE = registerBlock(
            "ice_ether_ore",
            () -> new Block(BlockBehaviour.Properties.ofFullCopy(Blocks.STONE)
                    .strength(3.5f, 3.0f)
                    .requiresCorrectToolForDrops())
    );

    // ================= ВСПОМОГАТЕЛЬНЫЕ МЕТОДЫ =================

    /**
     * Универсальный метод: регистрирует сам Block и автоматически создает для него BlockItem
     */
    private static <T extends Block> DeferredBlock<T> registerBlock(String name, Supplier<T> blockSupplier) {
        // Регистрируем сам блок
        DeferredBlock<T> registeredBlock = BLOCKS.register(name, blockSupplier);
        // Автоматически регистрируем соответствующий BlockItem в реестре предметов
        registerBlockItem(name, registeredBlock);
        return registeredBlock;
    }

    /**
     * Регистрация BlockItem в реестре ModItems.ITEMS
     */
    private static <T extends Block> void registerBlockItem(String name, DeferredBlock<T> block) {
        ModItems.ITEMS.register(name, () -> new BlockItem(block.get(), new Item.Properties()));
    }

    // Подключение к шине событий
    public static void register(IEventBus eventBus) {
        BLOCKS.register(eventBus);
    }
}
```

## 4. Регистрация шины событий и типичная ошибка запуска

В видео автор допустил классическую ошибку разработчика: забыл вызвать `ModBlocks.register(modEventBus)`. В результате игра выдала ошибку `IllegalStateException` при запуске мира.

Обязательно откройте главный класс (`TutorialMod.java`) и добавьте вызов в конструктор:

```java
public TutorialMod(IEventBus modEventBus) {
    // Регистрация предметов
    ModItems.register(modEventBus);
    // ОБЯЗАТЕЛЬНО: Регистрация блоков!
    ModBlocks.register(modEventBus);
    // Регистрация вкладок
    ModCreativeModeTabs.register(modEventBus);

    modEventBus.addListener(this::addCreative);
}
```

## 5. Добавление блоков в Creative Mode Tab

Откройте класс `ModCreativeModeTabs.java` и добавьте новые блоки в нужную вкладку (например, в основную `tutorial_tab`):

```java
.displayItems((parameters, output) -> {
    // Предметы
    output.accept(ModItems.ICE_ETHER.get());
    output.accept(ModItems.RAW_ICE_ETHER.get());

    // Блоки (передаем через .get())
    output.accept(ModBlocks.ICE_ETHER_BLOCK.get());
    output.accept(ModBlocks.RAW_ICE_ETHER_BLOCK.get());
    output.accept(ModBlocks.ICE_ETHER_ORE.get());
})
```

## 6. Структура ресурсов (Assets)

Для корректного отображения блока в мире и инвентаре требуется **4 типа JSON-файлов** и текстуры.

Структура папок мода:
```text
resources/assets/tutorial_mod/
 ├── blockstates/
 │    ├── ice_ether_block.json
 │    ├── raw_ice_ether_block.json
 │    └── ice_ether_ore.json
 ├── models/
 │    ├── block/
 │    │    ├── ice_ether_block.json
 │    │    ├── raw_ice_ether_block.json
 │    │    └── ice_ether_ore.json
 │    └── item/
 │         ├── ice_ether_block.json
 │         ├── raw_ice_ether_block.json
 │         └── ice_ether_ore.json
 ├── textures/
 │    └── block/
 │         ├── ice_ether_block.png
 │         ├── raw_ice_ether_block.png
 │         └── ice_ether_ore.png
 └── lang/
      └── en_us.json
```

### 6.1. Blockstate (`assets/tutorial_mod/blockstates/ice_ether_block.json`)
Связывает варианты состояния блока с его моделью. Для обычного кубического блока достаточно пустого варианта `""`:

```json
{
  "variants": {
    "": {
      "model": "tutorial_mod:block/ice_ether_block"
    }
  }
}
```
*(Аналогично создайте файлы для `raw_ice_ether_block.json` и `ice_ether_ore.json`)*.

---

### 6.2. Модель блока в мире (`assets/tutorial_mod/models/block/ice_ether_block.json`)
Использует родительскую ванильную модель `block/cube_all` (все 6 граней имеют одинаковую текстуру):

```json
{
  "parent": "block/cube_all",
  "textures": {
    "all": "tutorial_mod:block/ice_ether_block"
  }
}
```

---

### 6.3. Модель предмета в инвентаре (`assets/tutorial_mod/models/item/ice_ether_block.json`)
Чтобы предмет блока в инвентаре выглядел как миниатюрный 3D-куб, его модель просто наследует модель блока:

```json
{
  "parent": "tutorial_mod:block/ice_ether_block"
}
```

---

### 6.4. Локализация (`assets/tutorial_mod/lang/en_us.json`)
Ключи перевода для блоков начинаются с префикса `block.<mod_id>.<block_name>`:

```json
{
  "item.tutorial_mod.ice_ether": "Ice Ether",
  "item.tutorial_mod.raw_ice_ether": "Raw Ice Ether",
  "item.tutorial_mod.material.cardboard": "Cardboard",

  "block.tutorial_mod.ice_ether_block": "Ice Ether Block",
  "block.tutorial_mod.raw_ice_ether_block": "Raw Ice Ether Block",
  "block.tutorial_mod.ice_ether_ore": "Ice Ether Ore",

  "itemGroup.tutorial_tab": "Tutorial Tab",
  "itemGroup.material": "Material"
}
```

## 7. Кратко о сложных моделях и Blockbench

Для стандартных кубов файлы пишутся вручную за секунды. Но если вам понадобятся:
* Сложные состояния (ступени с ориентацией `facing=north/south/east/west`, заборы с составными частями `multipart`).
* Кастомная 3D-геометрия (стулья, столы, декорации).

Для этого используется бесплатная программа **Blockbench**:
* Выбирается формат **Java Block/Item** (или **GeckoLib Animated Model** для анимированных объектов).
* Созданная геометрия экспортируется прямо в `.json` модели проекта.

## 8. Тестирование в игре и почему блоки пока не выпадают

1. Запустите клиент (`Run Client`).
2. Зайдите в мир и откройте вкладку **Tutorial Tab**.
3. Возьмите созданные блоки:
    * Проверьте, что в руках и в инвентаре они отображаются как 3D-кубы с текстурами.
    * Установите блоки в мир: текстуры должны отображаться со всех 6 сторон, хитбокс и коллизия должны работать корректно.
4. **Вопрос:** *Почему при разрушении блока в режиме выживания из него ничего не выпадает?*
    * **Ответ:** За механику выпадения предметов отвечают **Таблицы лута (Loot Tables)**. Если таблица лута для блока не создана, игра по умолчанию считает, что блок ничего не дропает. Настройку лута мы подробно разберем в следующем уроке!
