## 1. Что такое рецепт и где он хранится

Рецепт в Minecraft — это обычный JSON-файл. Игра при загрузке мира читает все такие файлы и строит из них таблицу «что из чего получается». Ванильные рецепты устроены точно так же, поэтому лучший учебник — это сама игра: откройте в IntelliJ IDEA раздел **External Libraries** (Внешние библиотеки), найдите библиотеку с исходниками Minecraft и посмотрите папку `data/minecraft/recipe/`. Там лежат сотни готовых примеров.

Рецепты нашего мода хранятся по пути:

```text
src/main/resources/data/tutorial_mod/recipe/
```

> 💡 **Важное изменение в 1.21+:**  
> Папка рецептов называется **`recipe`** (в единственном числе), а не `recipes`. Если создать папку во множественном числе, игра просто не увидит ваши файлы и никакой ошибки не покажет.

> 💡 **Имя файла не имеет значения.**  
> В отличие от моделей и таблиц лута, у которых имя файла жёстко привязано к предмету или блоку, рецепт опознаётся по полю **`type`** внутри JSON. Файл можно назвать как угодно: имя нужно только как уникальный идентификатор (`tutorial_mod:имя_файла`). Единственные ограничения — только строчные латинские буквы, цифры и символы `_`, `-`, `.`. Заглавные буквы и кириллица запрещены.
>
> Это хорошо видно на ванильных примерах: каменную ступеньку можно скрафтить на верстаке, а можно вырезать камнерезом — это два разных рецепта с разными именами (например, `cobblestone_slab_from_cobblestone_stonecutting`), и игра различает их по `type`, а не по имени.
>
> Называйте файлы осмысленно (`<результат>_from_<способ>_<ингредиент>`), иначе через месяц вы не вспомните, что делает рецепт `12345.json`.

## 2. Верстак: форменный крафт (`crafting_shaped`)

Форменный (упорядоченный) рецепт требует, чтобы предметы стояли в сетке верстака **строго определённым образом**. Классический пример — лодка из пяти досок: две доски по краям верхнего ряда и три в нижнем ряду, «корытом».

Вот ванильный рецепт акациевой лодки:

```json
{
  "type": "minecraft:crafting_shaped",
  "category": "misc",
  "group": "boat",
  "key": {
    "#": {
      "item": "minecraft:acacia_planks"
    }
  },
  "pattern": [
    "# #",
    "###"
  ],
  "result": {
    "count": 1,
    "id": "minecraft:acacia_boat"
  }
}
```

### 2.1. Поля рецепта

| Поле | Назначение |
| :--- | :--- |
| `type` | Тип рецепта. Для форменного крафта — `minecraft:crafting_shaped`. **Единственное поле, по которому игра понимает, что это за рецепт.** |
| `category` | Вкладка в книге рецептов: `building`, `redstone`, `equipment` или `misc`. На сам крафт не влияет. |
| `group` | Необязательная строка-группа. Рецепты с одинаковой группой (например, лодки из разных досок) в книге рецептов показываются одной ячейкой. Название вы придумываете сами. |
| `key` | «Словарь» символов: какой символ шаблона какому предмету соответствует. |
| `pattern` | Сам шаблон — массив строк, который показывает расположение предметов в сетке. |
| `result` | Результат крафта: `id` — идентификатор предмета, `count` — количество. |

Вместе `pattern` и `key` — **самая важная часть** форменного рецепта: первое описывает *форму*, второе — *из чего она состоит*.

### 2.2. Правила шаблона (`pattern`)

Каждая строка массива `pattern` — это один ряд сетки верстака, а каждый символ в строке — одна клетка. Символ связывается с предметом через `key`. Для примера возьмём стрелу:

```json
{
  "type": "minecraft:crafting_shaped",
  "category": "equipment",
  "key": {
    "#": { "item": "minecraft:stick" },
    "X": { "item": "minecraft:flint" },
    "Y": { "item": "minecraft:feather" }
  },
  "pattern": [
    "X",
    "#",
    "Y"
  ],
  "result": {
    "count": 4,
    "id": "minecraft:arrow"
  }
}
```

Здесь использованы три разных символа: `X` (кремень), `#` (палка) и `Y` (перо). Символы могут быть любыми одиночными знаками — `#`, `X`, `Y`, `A`, `B`.

**Главные правила шаблона:**

1. **Все строки должны быть одинаковой длины.** Если в первой строке три символа, то и во второй должно быть ровно три. Рецепт лодки `"# #"` и `"###"` — обе строки по 3 символа.
2. **Пустая клетка обозначается пробелом.** В строке `"# #"` посередине стоит пробел — это значит, что средняя клетка пустая. Нельзя просто написать `"##"` — сдвиг клеток сломает рецепт.
3. **Нельзя «сокращать» строки.** Каждую клетку нужно описать явно, как в миске: `"# #"` и `" # "` (в нижней строке пробелы по бокам).
4. **Размер шаблона — от 1×1 до 3×3.** Рецепт можно выложить в любом месте сетки: игра сама сдвигает его. Поэтому «три свёклы в ряд» можно положить хоть в верхний, хоть в средний, хоть в нижний ряд верстака.
5. **Каждый символ из `pattern` должен быть описан в `key`**, иначе рецепт не загрузится.

> ⚠️ **Количество нельзя указать в `key`!**  
> В форменных (и бесформенных) рецептах каждая клетка сетки содержит **ровно один предмет**. Написать «возьми 3 доски в одну клетку» нельзя. Если вам нужно, чтобы расход предметов был нестандартным, ванильная система рецептов этого не умеет: придётся делать собственный тип рецепта или править ванильный код (через Mixin, что выходит за рамки этого курса).

### 2.3. Теги вместо предметов

Посмотрите на рецепт миски:

```json
{
  "type": "minecraft:crafting_shaped",
  "category": "misc",
  "key": {
    "#": {
      "tag": "minecraft:planks"
    }
  },
  "pattern": [
    "# #",
    " # "
  ],
  "result": {
    "count": 4,
    "id": "minecraft:bowl"
  }
}
```

Вместо `"item": "..."` здесь используется **`"tag": "minecraft:planks"`**. Это тег предметов: в нём собраны **все** виды досок (дубовые, акациевые, тёмного дуба и так далее). Благодаря этому одна запись подходит под любую доску.

Представьте, что тегов не существует. Чтобы палку можно было скрафтить из любых досок, пришлось бы писать отдельный рецепт для каждого вида дерева — по одному файлу на дуб, акацию, берёзу... Тег решает эту проблему: пишем один рецепт, а игра сама подставляет любую подходящую доску.

Тегами стоит пользоваться всегда, когда в рецепте подходит целое семейство предметов. Свои теги предметов мы создаём в Уроке 11, и после этого рецепты можно сделать ещё гибче.

## 3. Верстак: бесформенный крафт (`crafting_shapeless`)

В бесформенном рецепте положение предметов не важно: достаточно, чтобы все нужные ингредиенты лежали в сетке в любом порядке. Примеры из игры: книга (три бумаги и кожа), смешивание красителей, огненный заряд. Выше — рецепт книги.

Структура проще, чем у форменного: нет `key` и `pattern`, вместо них — список **`ingredients`**:

```json
{
  "type": "minecraft:crafting_shapeless",
  "category": "misc",
  "ingredients": [
    { "item": "minecraft:paper" },
    { "item": "minecraft:paper" },
    { "item": "minecraft:paper" },
    { "item": "minecraft:leather" }
  ],
  "result": {
    "count": 1,
    "id": "minecraft:book"
  }
}
```

Нужно три одинаковых ингредиента — запишите их три раза подряд, как три листа бумаги в примере. Ингредиентов в списке должно быть столько, сколько клеток сетки будет занято.

Бесформенные рецепты тоже поддерживают `"tag"` вместо `"item"`.

> 💡 **Форменный или бесформенный?**  
> Если предмет должен получаться только из определённой фигуры (инструменты, лодки, лестницы) — используйте форменный рецепт. Если важен только набор ингредиентов (смешивание, разборка блока на предметы) — бесформенный.

## 4. Рецепты готовки: печь, плавильная печь и костёр

Рецепты, которые «готовятся» с течением времени, устроены одинаково, различается только `type`:

| Блок | `type` |
| :--- | :--- |
| Печь (Furnace) | `minecraft:smelting` |
| Плавильная печь (Blast Furnace) | `minecraft:blasting` |
| Костёр (Campfire) | `minecraft:campfire_cooking` |

Пример ванильного рецепта костра — жарка говядины:

```json
{
  "type": "minecraft:campfire_cooking",
  "category": "food",
  "cookingtime": 600,
  "experience": 0.35,
  "ingredient": {
    "item": "minecraft:beef"
  },
  "result": {
    "id": "minecraft:cooked_beef"
  }
}
```

**Поля рецептов готовки:**

| Поле | Назначение |
| :--- | :--- |
| `category` | Вкладка книги рецептов: `food`, `blocks` или `misc`. |
| `group` | Необязательная группа (как и в верстаке). |
| `ingredient` | Входной предмет (один) — то, что кладём в печь. Тоже может быть `item` или `tag`. |
| `result` | Результат готовки. Поле `count` здесь не нужно — всегда получается один предмет. |
| `experience` | Сколько опыта получит игрок за один приготовленный предмет. |
| `cookingtime` | Время готовки **в тиках** (20 тиков = 1 секунда). |

**Какое время используют ваниль?**
* Печь (`smelting`): **200 тиков** = 10 секунд.
* Плавильная печь (`blasting`): **100 тиков** = 5 секунд — она работает вдвое быстрее.
* Костёр (`campfire_cooking`): **600 тиков** = 30 секунд.

> 💡 **Один блок — один тип рецепта.**  
> Если вы хотите, чтобы сырой эфир переплавлялся **и в печи, и в плавильной печи**, нужно написать **два отдельных рецепта** (`smelting` и `blasting`). Рецепт для печи не работает в плавильной печи автоматически.

## 5. Остальные типы рецептов и их связь с блочными сущностями

Заглянув в ванильную папку `data/minecraft/recipe/`, вы увидите и другие типы рецептов:

* `minecraft:stonecutting` — камнерез;
* `minecraft:smithing_transform` и `minecraft:smithing_trim` — кузнечный стол (улучшение до незерита, отделка брони);
* `minecraft:smoking` — коптильня.

Закономерность простая: **у большинства блоков с логикой обработки предметов есть свой тип рецепта**. Верстак, печь, плавильная печь, коптильня, костёр, камнерез, кузнечный стол — всё это блочные сущности (или блоки с интерфейсом), каждая из которых «читает» рецепты своего типа.

Из этого правила есть исключение: **стол зачарований** не использует рецепты — его механика зачарования жёстко зашита в код.

Почему это важно для моддинга? Если вы будете делать собственные «промышленные» машины (дробилки, плавильни, сборщики) на основе блочных сущностей, то хорошей практикой будет **создать для них собственный тип рецепта**. Иначе пришлось бы зашивать все превращения предметов прямо в Java-код, и их нельзя было бы менять датапаками. Создание собственных типов рецептов мы разберём в уроках про блочные сущности.

## 6. Пишем рецепты для нашего мода

Теперь на практике. В папке `src/main/resources/data/tutorial_mod/` создайте директорию **`recipe`** (в единственном числе!) и добавьте в неё шесть JSON-файлов:

```text
src/main/resources/data/tutorial_mod/recipe/
├── ice_ether.json
├── ice_ether_block.json
├── ice_ether_from_smelting_raw_ice_ether.json
├── ice_ether_from_blasting_raw_ice_ether.json
├── ice_ether_ore.json
└── sugar_from_beetroot.json
```

### 6.1. Блок эфира из 9 единиц эфира (форменный)

**Файл `ice_ether_block.json`** — девять единиц эфира, заполняющих всю сетку 3×3, превращаются в блок:

```json
{
  "type": "minecraft:crafting_shaped",
  "category": "building",
  "key": {
    "#": {
      "item": "tutorial_mod:ice_ether"
    }
  },
  "pattern": [
    "###",
    "###",
    "###"
  ],
  "result": {
    "count": 1,
    "id": "tutorial_mod:ice_ether_block"
  }
}
```

Символ `#` связан с предметом `tutorial_mod:ice_ether`, шаблон — три строки по три символа, значит, нужно заполнить всю сетку 3×3. Результат — один `tutorial_mod:ice_ether_block`.

### 6.2. 9 единиц эфира из блока (бесформенный)

**Файл `ice_ether.json`** — обратный рецепт: один блок распадается на девять единиц эфира. Здесь один ингредиент, поэтому форма не имеет значения, и подойдёт бесформенный рецепт:

```json
{
  "type": "minecraft:crafting_shapeless",
  "category": "misc",
  "ingredients": [
    {
      "item": "tutorial_mod:ice_ether_block"
    }
  ],
  "result": {
    "count": 9,
    "id": "tutorial_mod:ice_ether"
  }
}
```

Обратите внимание: количество `9` записано в **`result`**, а не в ингредиенте. Ингредиент всегда один предмет, а в результате мы можем получить любое количество.

### 6.3. Переплавка сырого эфира в печи

**Файл `ice_ether_from_smelting_raw_ice_ether.json`:**

```json
{
  "type": "minecraft:smelting",
  "category": "misc",
  "cookingtime": 200,
  "experience": 0.7,
  "group": "ice_ether",
  "ingredient": {
    "item": "tutorial_mod:raw_ice_ether"
  },
  "result": {
    "id": "tutorial_mod:ice_ether"
  }
}
```

Сырой эфир (`raw_ice_ether`) за 200 тиков (10 секунд) превращается в эфир (`ice_ether`) и приносит 0.7 опыта.

### 6.4. Переплавка сырого эфира в плавильной печи

**Файл `ice_ether_from_blasting_raw_ice_ether.json`** — копия предыдущего рецепта с двумя изменениями: тип `minecraft:blasting` и время `100` тиков (плавильная печь вдвое быстрее):

```json
{
  "type": "minecraft:blasting",
  "category": "misc",
  "cookingtime": 100,
  "experience": 0.7,
  "group": "ice_ether",
  "ingredient": {
    "item": "tutorial_mod:raw_ice_ether"
  },
  "result": {
    "id": "tutorial_mod:ice_ether"
  }
}
```

> 💡 **Совет по работе в IntelliJ IDEA:**  
> Чтобы не набирать похожие рецепты заново, копируйте файл (клавиша `F5` на файле в дереве проекта), задавайте новое имя и правьте только отличающиеся поля.

У обоих рецептов одинаковая **`group`** (`ice_ether`): в книге рецептов они будут показаны как один рецепт с двумя вариантами.

### 6.5. Руда эфира из сырого эфира и камня

**Файл `ice_ether_ore.json`** — «обратный» рецепт, который позволяет собрать руду из сырого эфира и камня. Это бесформенный рецепт с двумя ингредиентами:

```json
{
  "type": "minecraft:crafting_shapeless",
  "category": "building",
  "ingredients": [
    {
      "item": "tutorial_mod:raw_ice_ether"
    },
    {
      "item": "minecraft:stone"
    }
  ],
  "result": {
    "count": 1,
    "id": "tutorial_mod:ice_ether_ore"
  }
}
```

> ⚠️ **Частая ошибка:**  
> В первом ингредиенте нужно указывать именно **`raw_ice_ether`** (сырой эфир), а не `ice_ether`. Они отличаются только приставкой `raw_`, и при копировании рецептов её легко забыть.

### 6.6. Сахар из свёклы (рецепт для ванильного предмета)

**Файл `sugar_from_beetroot.json`** — свёкла, как и сахарный тростник, — сахарная культура. Сделаем так, чтобы три свёклы в ряд превращались в три единицы сахара:

```json
{
  "type": "minecraft:crafting_shaped",
  "category": "misc",
  "key": {
    "#": {
      "item": "minecraft:beetroot"
    }
  },
  "pattern": [
    "###"
  ],
  "result": {
    "count": 3,
    "id": "minecraft:sugar"
  }
}
```

Этот рецепт показывает две важные вещи:

1. **Моды могут добавлять рецепты для ванильных предметов.** В `key` и `result` можно использовать любые предметы с любыми пространствами имён — `minecraft:`, `tutorial_mod:` или предметы других модов.
2. **Шаблон может быть не квадратным.** Здесь он состоит из одной строки в три клетки.

> 💡 **Этот рецепт не заменяет ванильный.**  
> Идентификатор нашего рецепта — `tutorial_mod:sugar_from_beetroot`, а ванильный рецепт сахара из тростника — `minecraft:sugar_from_sugar_cane`. Это разные идентификаторы, поэтому оба рецепта работают одновременно. Если бы вы положили файл с тем же именем в `data/minecraft/recipe/`, он **перезаписал** бы ванильный рецепт.

## 7. Рецепты и достижения (Advancements)

Есть ещё один механизм, который связан с рецептами, — **достижения (advancements)**.

Откройте в игре книгу рецептов (кнопка рядом со слотами крафта в инвентаре): там отображаются **не все существующие рецепты, а только открытые**. Рецепты открываются автоматически, когда игрок выполняет некоторое условие: например, берёт в руки нужный предмет. В этот момент в правом верхнем углу экрана появляется уведомление «Рецепт открыт» (Recipe unlocked). За это отвечают **скрытые достижения**, которые не видны в меню `L` в игре, но работают «за кулисами».

Для нашего мода это значит, что рецепты из JSON-файлов будут **работать при крафте** в любом случае (если вы выложите ингредиенты в сетку, результат появится), но в книге рецептов они не отобразятся, пока игрок не получит соответствующее достижение.

Писать достижения вручную для каждого рецепта слишком утомительно, поэтому в нормальном моде их **генерируют автоматически** через DataGen: достаточно добавить к рецепту вызов `.unlockedBy(...)`, и достижение создастся само. Подробно это разобрано в Уроке 7.

> 💡 **Как открыть рецепт принудительно для теста:**  
> Команда `/recipe give @s tutorial_mod:ice_ether_block` открывает один рецепт, а `/recipe give @s *` открывает сразу все существующие рецепты, включая ванильные.

## 8. Тестирование в игре

1. Запустите конфигурацию **`Run Client`** и войдите в тестовый мир (в режиме творчества, чтобы быстро получить предметы).
2. **Форменный рецепт.** Заполните сетку верстака девятью единицами `Ice Ether` — на выходе появится `Ice Ether Block`.
3. **Бесформенный рецепт.** Положите в верстак один `Ice Ether Block` в любую клетку — получите 9 единиц `Ice Ether`.
4. **Руда.** Положите в верстак `Raw Ice Ether` и камень (`Stone`) в любых клетках — получите `Ice Ether Ore`.
5. **Печь и плавильная печь.** Поставьте печь и плавильную печь, положите в каждую `Raw Ice Ether` и уголь в качестве топлива. Оба блока выдадут `Ice Ether`, но в плавильной печи это произойдёт вдвое быстрее (5 секунд против 10).
6. **Сахар.** Выложите три свёклы в один ряд (в любом из трёх рядов сетки) — получите три единицы `Sugar`. Вторая проверка: обычный сахар из тростника тоже по-прежнему работает.

Если рецепт не появился в книге рецептов, а крафт работает — это нормально, см. раздел 7. Выдайте себе рецепты командой `/recipe give @s *`.

> 💡 **Редактируете JSON при запущенной игре?**  
> Если изменили файл рецепта, перезапустите клиент или хотя бы выйдите из мира и зайдите снова, чтобы игра заново прочитала данные.

## 9. Частые ошибки

* **Рецепт вообще не работает.** Проверьте путь: `data/tutorial_mod/recipe/` (не `recipes`!) и `tutorial_mod` — это идентификатор вашего мода.
* **В консоли ошибка парсинга рецепта (`Parsing error loading recipe`).** В JSON опечатка: пропущена запятая или скобка, неверный `type`, неправильный идентификатор предмета. В логе будет указано имя проблемного файла — открывайте его и проверяйте.
* **Форменный рецепт не распознаётся.** Строки в `pattern` разной длины, пустая клетка не заменена пробелом или символ из шаблона не описан в `key`.
* **Рецепт для печи работает, а для плавильной печи нет.** Нужен отдельный рецепт с `type: minecraft:blasting`.
* **Хочу указать количество ингредиента.** Нельзя: каждая клетка хранит один предмет. Количество задаётся только в `result`.
* **Назвал файл с заглавными буквами или кириллицей.** Игра не загрузит такой ресурс. Используйте только `a-z`, `0-9`, `_`, `-`, `.`.
