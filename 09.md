# Урок 9: Создание топлива для печей (Fuels & Burn Time) в NeoForge 1.21.1

В этом уроке мы разберем механику горючих материалов в Minecraft. Топливо — важнейший ресурс как в чистой игре (переплавка руд, приготовление пищи), так и в индустриальных модификациях (генерация энергии).

В современных версиях **NeoForge 1.21.1** существует **два принципиально разных способа** сделать предмет топливом:
1. **Классический способ через Java-код:** создание собственного класса предмета и переопределение метода `getBurnTime` из расширения `IItemExtension`.
2. **Современный способ через Data Maps (Дата-карты):** регистрация обычного предмета без создания лишних Java-классов и привязка времени горения через встроенный механизм DataGen (`DataMapProvider`).

Мы подробно реализуем оба метода на примере двух видов антрацита (**Anthracite** и **Anthracite 2**), сравним их преимущества и протестируем их работу в игре.

## 1. Теория: Как устроено время горения (Burn Time) в Minecraft

Время горения любого топлива в игре измеряется в **тиках** (1 секунда = 20 игровых тиков).

Для переплавки одного предмета в стандартной печи требуется ровно **200 тиков** (10 секунд):
* **Уголь / Древесный уголь:** `1600` тиков (80 секунд) $\rightarrow$ переплавляет $1600 / 200 = 8$ предметов.
* **Угольный блок:** `16000` тиков (800 секунд) $\rightarrow$ переплавляет 80 предметов.
* **Ведро лавы:** `20000` тиков (1000 секунд) $\rightarrow$ переплавляет 100 предметов.
* **Палка / Саженец:** `100` тиков (5 секунд) $\rightarrow$ переплавляет 0.5 предмета.

В ванильном коде все стандартные виды топлива жестко прописаны внутри статического метода `AbstractFurnaceBlockEntity.getFuel()`. Однако NeoForge предоставляет моддерам гибкие механизмы добавления собственного горючего.

## 2. Способ 1: Создание кастомного класса предмета (`ModFuelItem`)

Первый подход заключается в написании отдельного класса предмета.

В ванильном классе `Item` нет метода `getBurnTime`. Однако NeoForge неявно внедряет в `Item` интерфейс расширения **`IItemExtension`** (`net.neoforged.neoforge.common.extensions.IItemExtension`), содержащий виртуальный метод `getBurnTime`.

### Создание класса `ModFuelItem`:
1. В пакете мода создайте подпакет `item.custom`.
2. Внутри создайте класс `ModFuelItem.java`:

```java
package com.besson.tutorial.item.custom;

import net.minecraft.world.item.Item;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.crafting.RecipeType;
import org.jetbrains.annotations.Nullable;

public class ModFuelItem extends Item {
    private final int burnTime;

    /**
     * @param properties базовые свойства предмета (стак, вкладка и т.д.)
     * @param burnTime время горения предмета в тиках (200 тиков = 1 переплавка)
     */
    public ModFuelItem(Properties properties, int burnTime) {
        super(properties);
        this.burnTime = burnTime;
    }

    /**
     * Метод из интерфейса IItemExtension NeoForge.
     * Вызывается печью при проверке, является ли предмет горючим.
     */
    @Override
    public int getBurnTime(ItemStack itemStack, @Nullable RecipeType<?> recipeType) {
        return this.burnTime;
    }
}
```

> ⚠️ **Обратите внимание на сигнатуру метода:**  
> Переопределяйте именно метод с двумя параметрами: `getBurnTime(ItemStack itemStack, @Nullable RecipeType<?> recipeType)`. Устаревшие перегрузки без параметров использовать не следует.

## 3. Способ 2: Использование Data Maps в NeoForge (`ModDataMapProvider`)

Начиная с современных версий NeoForge, разработчикам больше **не обязательно** плодить собственные Java-классы ради изменения времени горения, компостирования или урона от падения. Для этого была разработана система **Data Maps (Дата-карты)**.

Дата-карта связывает идентификатор любого стандартного предмета с определенными данными через JSON-файлы формата:  
`data/neoforge/data_maps/item/furnace_fuels.json`.

Вместо ручного написания JSON мы воспользуемся DataGen-провайдером **`DataMapProvider`**.

### Создание класса `ModDataMapProvider`:
В пакете `datagen` создайте класс `ModDataMapProvider.java`:

```java
package com.besson.tutorial.datagen;

import com.besson.tutorial.item.ModItems;
import net.minecraft.core.HolderLookup;
import net.minecraft.data.PackOutput;
import net.neoforged.neoforge.common.data.DataMapProvider;
import net.neoforged.neoforge.registries.datamaps.builtin.FurnaceFuel;
import net.neoforged.neoforge.registries.datamaps.builtin.NeoForgeDataMaps;

import java.util.concurrent.CompletableFuture;

public class ModDataMapProvider extends DataMapProvider {

    public ModDataMapProvider(PackOutput packOutput, CompletableFuture<HolderLookup.Provider> lookupProvider) {
        super(packOutput, lookupProvider);
    }

    @Override
    protected void gather() {
        // Привязываем время горения (1600 тиков) к обычному предмету ANTHRACITE_2
        this.builder(NeoForgeDataMaps.FURNACE_FUELS)
                .add(ModItems.ANTHRACITE_2.getId(), new FurnaceFuel(1600), false);
    }
}
```

* `NeoForgeDataMaps.FURNACE_FUELS` — стандартная дата-карта топлива NeoForge.
* `.add(ResourceLocation, FurnaceFuel, boolean replace)` — регистрирует ID предмета, время его горения в тиках и флаг замещения существующих значений (`false` = добавить к существующим).

## 4. Регистрация предметов топлива в `ModItems`

Откройте класс `ModItems.java` и зарегистрируйте два предмета:
1. **`ANTHRACITE`** — экземпляр `ModFuelItem` (Способ 1).
2. **`ANTHRACITE_2`** — обычный ванильный `Item` (Способ 2, чье поведение горения задается через Data Map).

```java
package com.besson.tutorial.item;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.item.custom.ModFuelItem;
import net.minecraft.world.item.Item;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredItem;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModItems {
    public static final DeferredRegister.Items ITEMS = 
            DeferredRegister.createItems(TutorialMod.MOD_ID);

    // ================= ТОПЛИВО =================
    // 1. Способ через кастомный класс (1600 тиков = 8 предметов)
    public static final DeferredItem<Item> ANTHRACITE = ITEMS.register(
            "anthracite",
            () -> new ModFuelItem(new Item.Properties(), 1600)
    );

    // 2. Способ через обычный Item (время горения задается через DataMap)
    public static final DeferredItem<Item> ANTHRACITE_2 = ITEMS.register(
            "anthracite_2",
            () -> new Item(new Item.Properties())
    );

    // Предметы из предыдущих уроков...
    public static final DeferredItem<Item> ICE_ETHER = ITEMS.register("ice_ether", () -> new Item(new Item.Properties()));
    public static final DeferredItem<Item> RAW_ICE_ETHER = ITEMS.register("raw_ice_ether", () -> new Item(new Item.Properties()));
    public static final DeferredItem<Item> CARDBOARD = ITEMS.register("material/cardboard", () -> new Item(new Item.Properties()));

    public static void register(IEventBus eventBus) {
        ITEMS.register(eventBus);
    }
}
```

## 6. Настройка DataGen (модели, локализация, дата-карты)

### 6.1. Регистрация `ModDataMapProvider` в `ModDataGenerator`
Откройте класс `ModDataGenerator.java` и подключите новый серверный провайдер в метод `gatherData`:

```java
// Серверные данные: Регистрация Data Maps
generator.addProvider(event.includeServer(), new ModDataMapProvider(packOutput, lookupProvider));
```

### 6.2. Модели предметов (`ModItemModelProvider`)
Откройте `ModItemModelProvider.java` и сгенерируйте 2D-модели для обоих видов топлива:

```java
@Override
protected void registerModels() {
    basicItem(ModItems.ICE_ETHER.get());
    basicItem(ModItems.RAW_ICE_ETHER.get());
    basicItem(ModItems.CARDBOARD.get());
    basicItem(ModItems.STRAWBERRY.get());

    // Модели для топлива
    basicItem(ModItems.ANTHRACITE.get());
    basicItem(ModItems.ANTHRACITE_2.get());
}
```

## 7. Разбор типичной ошибки: дублирование ID регистрации

В процессе демонстрации автор урока столкнулся с распространенной ошибкой: при копировании строки регистрации нового предмета было забыто изменение внутреннего строкового идентификатора:

```java
// ОШИБКА: два разных поля регистрируют один и тот же путь "anthracite"
public static final DeferredItem<Item> ANTHRACITE = ITEMS.register("anthracite", ...);
public static final DeferredItem<Item> ANTHRACITE_2 = ITEMS.register("anthracite", ...);
```

При запуске задачи `runData` или клиента игра упадет с ошибкой:
```text
java.lang.IllegalArgumentException: Duplicate registration anthracite
BUILD FAILED
```
> 💡 **Правило:** Каждый зарегистрированный объект обязан обладать уникальным строковым идентификатором в пределах вашего мода (`"anthracite"` и `"anthracite_2"`).

## 8. Тестирование в обычной печи и плавильне

1. Выполните генерацию ресурсов через конфигурацию **`Run Data`** (или команду `./gradlew runData`).
2. Загляните в сгенерированные файлы: в папке `data/neoforge/data_maps/item/` появился файл `furnace_fuels.json`:
   ```json
   {
     "values": {
       "tutorial_mod:anthracite_2": {
         "burn_time": 1600
       }
     }
   }
   ```
3. Запустите игру через конфигурацию **`Run Client`**.
4. Войдите в мир и откройте творческий инвентарь:
    * Возьмите обычную печь (**Furnace**) и плавильню (**Blast Furnace**).
    * Возьмите стак руды или необработанного железа/эфира.
    * Возьмите созданные предметы: `Anthracite` и `Anthracite 2`.
5. **Тест 1 (Кастомный класс `Anthracite`):**
    * Положите `Anthracite` в нижний слот печи.
    * Огонь загорится: шкала горения начнет плавно уменьшаться, успевая переплавить ровно 8 единиц сырья.
6. **Тест 2 (Data Map `Anthracite 2`):**
    * Положите `Anthracite 2` в плавильню или печь.
    * Несмотря на то, что это обычный ванильный класс `Item`, благодаря дата-карте печь распознает его как полноценное горючее на 1600 тиков.

***

**Какой способ выбрать?**
* Используйте **Способ 2 (Data Maps)** во всех стандартных случаях: это чистый, современный подход NeoForge, не требующий создания вспомогательных классов-оберток.
* Используйте **Способ 1 (Кастомный класс)**, если вашему горючему требуется дополнительная динамическая логика (например, если время горения зависит от зачарований предмета, его износа или NBT-компонентов).
