# Урок 10: Создание предмета с уникальной логикой (Геологоразведчик / Prospector) в NeoForge 1.21.1

В предыдущих уроках мы создавали предметы с пассивными свойствами (топливо, еда). Пришло время написать первый по-настоящему интерактивный инструмент с собственной логикой взаимодействия с миром.

Мы создадим **Геологоразведчик (Prospector)** — прибор для поиска ценных руд под землей:
* При нажатии правой кнопкой мыши по блоку прибор сканирует толщу породы под ногами игрока.
* **Обычный режим:** сканирует область 5×5 блоков на всю глубину вниз.
* **Точный режим (на корточках / `Shift`):** сканирует только одну вертикальную колонну прямо под выбранным блоком.
* При обнаружении руды прибор отправляет в чат сообщение с точными координатами залежей.
* Каждое использование тратит единицу прочности (`durability`).

В ходе урока мы разберем ключевые концепции моддинга: методы `useOn`, разделение логики Клиент/Сервер (`Level.isClientSide`), работу с координатами `BlockPos`, трату прочности `hurtAndBreak` и оптимизацию циклов сканирования.

## 1. Теория: Методы взаимодействия предмета и разделение Клиент/Сервер

### 1.1. `use` против `useOn`
В базовом классе `net.minecraft.world.item.Item` есть два ключевых метода обработки клика ПКМ:
* **`use(Level level, Player player, InteractionHand hand)`:** срабатывает при клике ПКМ в воздух (так работают жемчуг Края, луки, еда, зелья).
* **`useOn(UseOnContext context)`:** срабатывает **только при клике по конкретному блоку**. Объект `context` содержит всю необходимую информацию: по какому блоку кликнули (`getClickedPos`), какой игрок (`getPlayer`), в каком мире (`getLevel`) и какой гранью блока коснулись. Для прибора поиска руд нам нужен именно `useOn`.

### 1.2. Клиент против Сервера (`level.isClientSide()`)
Minecraft работает по клиент-серверной архитектуре (даже в одиночной игре запускается встроенный локальный сервер):
* **Клиент (Client):** отвечает за отрисовку графики, анимации и проигрывание звуков.
* **Сервер (Server):** производит все вычисления, управляет инвентарями, блоками, мобами и игровой логикой.

> ⚠️ **Железное правило:**  
> Все важные игровые действия (трата прочности, сканирование блоков, отправка сообщений) должны выполняться **только на стороне сервера**:
> ```java
> if (!level.isClientSide()) {
>     // Серверная логика
> }
> ```

## 2. Создание класса `ProspectorItem`

В пакете `com.besson.tutorial.item.custom` создайте класс `ProspectorItem.java`:

```java
package com.besson.tutorial.item.custom;

import net.minecraft.core.BlockPos;
import net.minecraft.network.chat.Component;
import net.minecraft.world.InteractionResult;
import net.minecraft.world.entity.EquipmentSlot;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.item.Item;
import net.minecraft.world.item.context.UseOnContext;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.Blocks;
import net.minecraft.world.level.block.state.BlockState;

public class ProspectorItem extends Item {

    public ProspectorItem(Properties properties) {
        super(properties);
    }

    @Override
    public InteractionResult useOn(UseOnContext context) {
        Level level = context.getLevel();
        Player player = context.getPlayer();
        BlockPos clickedPos = context.getClickedPos();

        // Выполняем логику строго на стороне сервера
        if (!level.isClientSide() && player != null) {
            boolean foundOre = false;

            // Проверяем, зажата ли клавиша Shift (игрок крадется)
            if (player.isCrouching()) {
                // Точечный режим: сканируем одну вертикальную колонну вниз
                foundOre = scanColumn(level, clickedPos, player);
            } else {
                // Обычный режим: сканируем область 5x5 блоков вниз
                foundOre = scanArea(level, clickedPos, player);
            }

            if (!foundOre) {
                player.sendSystemMessage(Component.translatable("chat.tutorial_mod.prospector.no_ore_found"));
            }

            // Тратим 1 единицу прочности в главной руке
            context.getItemInHand().hurtAndBreak(1, player, EquipmentSlot.MAINHAND);
        }

        return InteractionResult.SUCCESS;
    }

    /**
     * Сканирование вертикальной колонны вниз (режим приседания)
     */
    private boolean scanColumn(Level level, BlockPos startPos, Player player) {
        for (int y = startPos.getY(); y >= level.getMinBuildHeight(); y--) {
            BlockPos currentPos = new BlockPos(startPos.getX(), y, startPos.getZ());
            BlockState state = level.getBlockState(currentPos);

            if (isValuableBlock(state)) {
                outputValuableCoordinates(currentPos, player, state.getBlock());
                return true;
            }
        }
        return false;
    }

    /**
     * Сканирование области 5x5 блоков вниз (обычный режим)
     */
    private boolean scanArea(Level level, BlockPos startPos, Player player) {
        // Радиус 2 блока вокруг центральной точки (от -2 до +2 дает область 5x5)
        for (int x = -2; x <= 2; x++) {
            for (int z = -2; z <= 2; z++) {
                for (int y = startPos.getY(); y >= level.getMinBuildHeight(); y--) {
                    BlockPos currentPos = startPos.offset(x, y - startPos.getY(), z);
                    BlockState state = level.getBlockState(currentPos);

                    if (isValuableBlock(state)) {
                        outputValuableCoordinates(currentPos, player, state.getBlock());
                        return true;
                    }
                }
            }
        }
        return false;
    }

    /**
     * Отправка найденных координат в чат игрока
     */
    private void outputValuableCoordinates(BlockPos pos, Player player, Block block) {
        player.sendSystemMessage(Component.translatable(
                "chat.tutorial_mod.prospector.ore_found",
                block.getName().getString(),
                pos.getX(),
                pos.getY(),
                pos.getZ()
        ));
    }

    /**
     * Список ценных руд, на которые реагирует детектор
     */
    private boolean isValuableBlock(BlockState state) {
        return state.is(Blocks.DIAMOND_ORE) 
                || state.is(Blocks.DEEPSLATE_DIAMOND_ORE)
                || state.is(Blocks.ANCIENT_DEBRIS)
                || state.is(Blocks.IRON_ORE)
                || state.is(Blocks.DEEPSLATE_IRON_ORE);
    }
}
```

### Пояснения по ключевым методам:
1. **`player.isCrouching()`** — проверяет состояние приседания игрока на сервере.
2. **`level.getMinBuildHeight()`** — минимальная высота мира (в современных версиях это `Y = -64`).
3. **`player.sendSystemMessage(Component)`** — отправляет системное сообщение в левый нижний угол экрана (чат).
4. **`context.getItemInHand().hurtAndBreak(1, player, EquipmentSlot.MAINHAND)`** — отнимает 1 единицу прочности у предмета. При исчерпании лимита предмет автоматически ломается с проигрыванием стандартного звука поломки.

## 3. Регистрация предмета в `ModItems`

Откройте класс `ModItems.java`. Зарегистрируйте геологоразведчик с ограничением прочности в **128 использований** через метод `.durability(128)`:

```java
// ================= ИНСТРУМЕНТЫ =================
public static final DeferredItem<Item> PROSPECTOR = ITEMS.register(
        "prospector",
        () -> new ProspectorItem(new Item.Properties().durability(128))
);
```

> 💡 **Замечание:** Указание `.durability(...)` автоматически устанавливает максимальный размер стака равным 1 (инструменты с прочностью не стакаются).

## 6. Производительность: почему вложенные циклы не крашат сервер

В видео автор подробно останавливается на вопросе нагрузки на процессор (CPU) из-за трех вложенных циклов `for` ($5 \times 5 \times 100 \approx 2500$ итераций):

1. **Разовое действие против постоянного тика:**  
   Если запускать поиск руды **каждый тик** (20 раз в секунду в методе `inventoryTick`), сервер мгновенно зависнет от колоссальной нагрузки (задержка тика превысит 50 мс).
2. **Клик игрока (User Interaction):**  
   Метод `useOn` выполняется **только в момент нажатия ПКМ**.
3. **Быстрый выход из цикла (`break` / `return`):**  
   Благодаря оператору `return true` при первом же нахождении блока цикл немедленно прерывается, не продолжая обход остальных тысяч блоков.
4. В панели отладки `F3` задержка встроенного сервера (*Built-in server*) при нажатии поднимается всего на **1–2 миллисекунды**, что абсолютно незаметно даже на слабых компьютерах.

## 7. Тестирование в игре

1. Запустите конфигурацию **`Run Data`** для генерации новых JSON-файлов.
2. Запустите игру через **`Run Client`**.
3. Выдайте себе инструмент из вкладки мода.
4. Переключитесь в режим выживания (`/gamemode survival`).
5. **Тест 1 (Поиск в области 5×5):**
    * Кликните ПКМ по поверхности земли над залежами руды (или предварительно закопайте алмазную руду на глубине).
    * В чате появится зеленое сообщение:  
      `Найдена руда Алмазная руда на координатах (X, Y, Z)!`
    * Обратите внимание на полоску износа инструмента — прочность уменьшилась на 1.
6. **Тест 2 (Точный режим с зажатым `Shift`):**
    * Зажмите `Shift` и кликните ПКМ в сторону от руды: прибор проверит только одну колонну и выдаст сообщение: *«Поблизости ценных руд не обнаружено.»*
    * Присядьте ровно над рудой и кликните — прибор найдет её.
