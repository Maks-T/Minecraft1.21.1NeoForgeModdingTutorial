# Урок 11: Кастомные теги блоков и предметов (Tags) в NeoForge 1.21.1

В Уроке 10 мы создали геологоразведчик (`ProspectorItem`), однако проверка ценных руд была жестко захардкожена в Java-коде (`Blocks.DIAMOND_ORE`, `Blocks.IRON_ORE` и т. д.). Из-за этого другие модификации или дата-паки не могли расширить список обнаруживаемых руд без перекомпиляции мода.

В этом уроке мы исправим этот недостаток с помощью **системы тегов (Tags)** Minecraft:
* Разберем концепцию тегов для блоков (`BlockTags`) и предметов (`ItemTags`).
* Создадим класс `ModTags` для централизованного объявления кастомных тегов.
* Переведем геологоразведчик на проверку через тег `prospector_ores`.
* Создадим тег предметов `sugar_ingredients` и перепишем рецепт сахара, сделав его совместимым с любыми продуктами из тега (картон, клубника, свекла).
* Настроим автогенерацию тегов через **DataGen**.

## 1. Теория: Зачем нужны теги в Minecraft

**Тег (Tag)** — это именованная группа объектов (блоков, предметов, сущностей, жидкостей или биомов), определяемая в JSON-файлах дата-пака.

### Преимущества использования тегов:
1. **Гибкость и совместимость модов (Mod Compatibility):**  
   Вместо проверки конкретного предмета рецепт или инструмент ссылается на группу. Например, ванильный верстак принимает любые доски из тега `#minecraft:planks`, а печь плавит любые железные руды из тега `#c:ores/iron`.
2. **Расширяемость дата-паками:**  
   Создатели сборок могут через JSON добавить любой ванильный или сторонний блок в тег вашего мода, не меняя Java-код.
3. **Общие конвенционные теги (`c:`):**  
   В современных версиях NeoForge и Fabric для межмодовой совместимости принят единый стандарт `c` (Conventional Tags): `#c:ores`, `#c:ingots/copper`, `#c:tools/pickaxes` и т. д.

## 2. Создание класса регистрации тегов (`ModTags`)

1. В пакете вашего мода создайте подпакет `tag` (или `util`).
2. Внутри создайте класс `ModTags.java`.

Теги создаются с помощью фабричных методов `BlockTags.create(...)` и `ItemTags.create(...)`, принимающих `ResourceLocation`:

```java
package com.besson.tutorial.tag;

import com.besson.tutorial.TutorialMod;
import net.minecraft.core.registries.Registries;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.tags.BlockTags;
import net.minecraft.tags.ItemTags;
import net.minecraft.tags.TagKey;
import net.minecraft.world.item.Item;
import net.minecraft.world.level.block.Block;

public class ModTags {

    // ================= ТЕГИ БЛОКОВ =================
    public static class Blocks {
        // Тег руд, на которые реагирует геологоразведчик
        public static final TagKey<Block> PROSPECTOR_ORES = tag("prospector_ores");

        private static TagKey<Block> tag(String name) {
            return TagKey.create(Registries.BLOCK, ResourceLocation.fromNamespaceAndPath(TutorialMod.MOD_ID, name));
        }
    }

    // ================= ТЕГИ ПРЕДМЕТОВ =================
    public static class Items {
        // Тег ингредиентов, из которых можно синтезировать сахар
        public static final TagKey<Item> SUGAR_INGREDIENTS = tag("sugar_ingredients");

        private static TagKey<Item> tag(String name) {
            return TagKey.create(Registries.ITEM, ResourceLocation.fromNamespaceAndPath(TutorialMod.MOD_ID, name));
        }
    }
}
```

## 3. Рефакторинг геологоразведчика под тег руд

Откройте класс `ProspectorItem.java` из Урока 10. Найдите метод `isValuableBlock` и замените длинную цепочку условий `state.is(Blocks...)` на проверку тега:

```java
/**
 * Проверка руды через тег ModTags.Blocks.PROSPECTOR_ORES
 */
private boolean isValuableBlock(BlockState state) {
    return state.is(ModTags.Blocks.PROSPECTOR_ORES);
}
```

Всего одна строка `state.is(...)` полностью заменяет громоздкие перечисления и дает абсолютную свободу для расширения функционала прибора через JSON!

## 4. Генерация тегов через DataGen

Теперь наполним созданные теги значениями с помощью наших генераторов данных.

### 4.1. Наполнение тегов блоков (`ModBlockTagsProvider`)
Откройте `ModBlockTagsProvider.java` в пакете `datagen`. Добавьте в метод `addTags` наполнение нашего кастомного тега:

```java
@Override
protected void addTags(HolderLookup.Provider provider) {
    // Ванильные теги кирок из прошлых уроков
    tag(BlockTags.MINEABLE_WITH_PICKAXE)
            .add(ModBlocks.ICE_ETHER_BLOCK.get())
            .add(ModBlocks.RAW_ICE_ETHER_BLOCK.get())
            .add(ModBlocks.ICE_ETHER_ORE.get());

    tag(BlockTags.NEEDS_IRON_TOOL)
            .add(ModBlocks.ICE_ETHER_ORE.get());

    // ================= КАСТОМНЫЙ ТЕГ ДЕТЕКТОРА РУД =================
    tag(ModTags.Blocks.PROSPECTOR_ORES)
            // Добавляем руду нашего мода
            .add(ModBlocks.ICE_ETHER_ORE.get())
            // Добавляем конкретные ванильные блоки
            .add(Blocks.IRON_ORE, Blocks.DEEPSLATE_IRON_ORE)
            .add(Blocks.GOLD_ORE, Blocks.DEEPSLATE_GOLD_ORE)
            .add(Blocks.ANCIENT_DEBRIS)
            // Можно вкладывать целые ванильные теги целиком (все алмазные руды сразу)
            .addTag(BlockTags.DIAMOND_ORES);
}
```

> 💡 **Метод `.addTag(...)`:** Позволяет вложить один тег внутрь другого. Например, включив `BlockTags.DIAMOND_ORES`, мы автоматически добавили и обычную, и глубинносланцевую алмазную руду.

### 4.2. Наполнение тегов предметов (`ModItemTagsProvider`)
Откройте класс `ModItemTagsProvider.java` и наполните тег `SUGAR_INGREDIENTS`:

```java
package com.besson.tutorial.datagen;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.item.ModItems;
import com.besson.tutorial.tag.ModTags;
import net.minecraft.core.HolderLookup;
import net.minecraft.data.PackOutput;
import net.minecraft.data.tags.ItemTagsProvider;
import net.minecraft.world.item.Items;
import net.minecraft.world.level.block.Block;
import net.neoforged.neoforge.common.data.ExistingFileHelper;
import org.jetbrains.annotations.Nullable;

import java.util.concurrent.CompletableFuture;

public class ModItemTagsProvider extends ItemTagsProvider {

    public ModItemTagsProvider(PackOutput output, 
                               CompletableFuture<HolderLookup.Provider> lookupProvider, 
                               CompletableFuture<TagLookup<Block>> blockTags, 
                               @Nullable ExistingFileHelper existingFileHelper) {
        super(output, lookupProvider, blockTags, TutorialMod.MOD_ID, existingFileHelper);
    }

    @Override
    protected void addTags(HolderLookup.Provider provider) {
        // Предметы, которые считаются сахаросодержащим сырьем
        tag(ModTags.Items.SUGAR_INGREDIENTS)
                .add(ModItems.CARDBOARD.get())     // Картон
                .add(ModItems.STRAWBERRY.get())    // Клубника
                .add(Items.BEETROOT);              // Ванильная свекла
    }
}
```

## 5. Использование тегов в рецептах (`ModRecipeProvider`)

Откройте `ModRecipeProvider.java`. Ранее мы регистрировали бесформенный крафт сахара строго из картона:
`requires(ModItems.CARDBOARD.get())`.

Перепишем рецепт так, чтобы он принимал **любой предмет из тега `SUGAR_INGREDIENTS`**:

```java
// Бесформенный крафт сахара с использованием тега в качестве ингредиента
ShapelessRecipeBuilder.shapeless(RecipeCategory.MISC, Items.SUGAR, 1)
        // Принимаем любой предмет, входящий в тег
        .requires(Ingredient.of(ModTags.Items.SUGAR_INGREDIENTS))
        // Условие открытия рецепта в книге рецептов
        .unlockedBy("has_sugar_ingredient", has(ModTags.Items.SUGAR_INGREDIENTS))
        .save(output, ResourceLocation.fromNamespaceAndPath(TutorialMod.MOD_ID, "sugar_from_tag"));
```

Теперь игроку не обязательно иметь именно картон — он может положить в верстак клубнику или свеклу, и игра выдаст сахар по этому же рецепту.

## 6. Запуск генерации и проверка JSON-файлов

1. Запустите конфигурацию **`Run Data`** (или команду `./gradlew runData`).
2. Загляните в сгенерированные файлы:
    * `src/generated/resources/data/tutorial_mod/tags/block/prospector_ores.json`:
      ```json
      {
        "values": [
          "tutorial_mod:ice_ether_ore",
          "minecraft:iron_ore",
          "minecraft:deepslate_iron_ore",
          "minecraft:gold_ore",
          "minecraft:deepslate_gold_ore",
          "minecraft:ancient_debris",
          "#minecraft:diamond_ores"
        ]
      }
      ```
      *(Символ решетки `#` перед `minecraft:diamond_ores` обозначает вложенный тег)*.
    * `src/generated/resources/data/tutorial_mod/tags/item/sugar_ingredients.json`:
      ```json
      {
        "values": [
          "tutorial_mod:material/cardboard",
          "tutorial_mod:strawberry",
          "minecraft:beetroot"
        ]
      }
      ```
    * `src/generated/resources/data/tutorial_mod/recipe/sugar_from_tag.json`:  
      в блоке `ingredients` теперь указан `"tag": "tutorial_mod:sugar_ingredients"`.

## 7. Тестирование в игре

1. Запустите клиент игры (**`Run Client`**).
2. Зайдите в мир и откройте режим выживания.
3. **Тест 1 (Геологоразведчик с тегами):**
    * Возьмите инструмент `Prospector`.
    * Проверьте детектор на железной руде, золотой руде, алмазной руде и руде ледяного эфира (`Ice Ether Ore`).
    * Прибор безошибочно находит все типы руд, так как все они объединены тегом `#tutorial_mod:prospector_ores`.
4. **Тест 2 (Крафт сахара через тег):**
    * Подойдите к верстаку.
    * Положите в сетку крафта **картон** $\rightarrow$ на выходе получается сахар.
    * Положите **клубнику** $\rightarrow$ на выходе получается сахар.
    * Положите **свеклу** $\rightarrow$ на выходе получается сахар.
    * Попробуйте положить камень или яблоко $\rightarrow$ крафт не работает, так как этих предметов нет в теге.
