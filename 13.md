## 1. Теория: Архитектура декоративных блоков в 1.21+

### 1.1. Параметры звуков и поведения (`BlockSetType` и `WoodType`)
Начиная с версий 1.20+, Mojang унифицировали параметры кнопок, дверей и нажимных плит:
* **`BlockSetType`** — определяет тип материала: звуки нажатия кнопки/двери (дерево, камень, медь, железо) и поведение нажимной плиты (активируется ли только сущностями или также стрелами/выброшенными предметами). Для камня/кристаллов используется `BlockSetType.STONE`.
* **`WoodType`** — используется калитками (`FenceGateBlock`) для привязки звуков открывания.

---

### 1.2. Прозрачность и X-Ray баг: зачем нужен `.noOcclusion()`
По умолчанию движок рендеринга Minecraft считает каждый блок сплошным непрозрачным кубом $16 \times 16 \times 16$. Если блок не занимает весь куб (двери, люки, заборы, ступени) или имеет полупрозрачные пиксели в текстуре, необходимо вызвать метод:
```java
.noOcclusion()
```
Если этого не сделать, соседние блоки посчитают, что их грань закрыта, и не будут её отрисовывать. В результате сквозь щели двери игрок увидит пустоту под землей («эффект рентгена / X-Ray»).

## 2. Регистрация 9 типов блоков в `ModBlocks`

Откройте класс `ModBlocks.java` и добавьте регистрацию всех производных блоков. Свойства прочности и звуков скопируем с нашего `ICE_ETHER_BLOCK` через `Properties.ofFullCopy(...)`:

```java
package com.besson.tutorial.block;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.item.ModItems;
import net.minecraft.world.item.BlockItem;
import net.minecraft.world.item.Item;
import net.minecraft.world.level.block.*;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.minecraft.world.level.block.state.properties.BlockSetType;
import net.minecraft.world.level.block.state.properties.WoodType;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredBlock;
import net.neoforged.neoforge.registries.DeferredRegister;

import java.util.function.Supplier;

public class ModBlocks {
    public static final DeferredRegister.Blocks BLOCKS = 
            DeferredRegister.createBlocks(TutorialMod.MOD_ID);

    // Базовые блоки из прошлых уроков
    public static final DeferredBlock<Block> ICE_ETHER_BLOCK = registerBlock("ice_ether_block", 
            () -> new Block(BlockBehaviour.Properties.of().strength(3.0f).sound(SoundType.AMETHYST).requiresCorrectToolForDrops()));
    public static final DeferredBlock<Block> RAW_ICE_ETHER_BLOCK = registerBlock("raw_ice_ether_block", 
            () -> new Block(BlockBehaviour.Properties.of().strength(4.0f).sound(SoundType.STONE).requiresCorrectToolForDrops()));
    public static final DeferredBlock<Block> ICE_ETHER_ORE = registerBlock("ice_ether_ore", 
            () -> new Block(BlockBehaviour.Properties.ofFullCopy(Blocks.STONE).strength(3.5f).requiresCorrectToolForDrops()));

    // ================= СТРОИТЕЛЬНЫЕ И ДЕКОРАТИВНЫЕ БЛОКИ =================

    // 1. Ступени (первым параметром передается базовое состояние блока)
    public static final DeferredBlock<StairBlock> ICE_ETHER_STAIRS = registerBlock("ice_ether_stairs",
            () -> new StairBlock(ICE_ETHER_BLOCK.get().defaultBlockState(), 
                    BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get())));

    // 2. Полублок / Плита
    public static final DeferredBlock<SlabBlock> ICE_ETHER_SLAB = registerBlock("ice_ether_slab",
            () -> new SlabBlock(BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get())));

    // 3. Кнопка (20 тиков = 1 секунда нажатого состояния)
    public static final DeferredBlock<ButtonBlock> ICE_ETHER_BUTTON = registerBlock("ice_ether_button",
            () -> new ButtonBlock(BlockSetType.STONE, 20, 
                    BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get()).noCollission()));

    // 4. Нажимная плита
    public static final DeferredBlock<PressurePlateBlock> ICE_ETHER_PRESSURE_PLATE = registerBlock("ice_ether_pressure_plate",
            () -> new PressurePlateBlock(BlockSetType.STONE, 
                    BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get()).noCollission()));

    // 5. Забор
    public static final DeferredBlock<FenceBlock> ICE_ETHER_FENCE = registerBlock("ice_ether_fence",
            () -> new FenceBlock(BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get())));

    // 6. Калитка
    public static final DeferredBlock<FenceGateBlock> ICE_ETHER_FENCE_GATE = registerBlock("ice_ether_fence_gate",
            () -> new FenceGateBlock(WoodType.OAK, 
                    BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get())));

    // 7. Стена / Ограда
    public static final DeferredBlock<WallBlock> ICE_ETHER_WALL = registerBlock("ice_ether_wall",
            () -> new WallBlock(BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get())));

    // 8. Дверь (Обязательно .noOcclusion())
    public static final DeferredBlock<DoorBlock> ICE_ETHER_DOOR = registerBlock("ice_ether_door",
            () -> new DoorBlock(BlockSetType.STONE, 
                    BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get()).noOcclusion()));

    // 9. Люк (Обязательно .noOcclusion())
    public static final DeferredBlock<TrapDoorBlock> ICE_ETHER_TRAPDOOR = registerBlock("ice_ether_trapdoor",
            () -> new TrapDoorBlock(BlockSetType.STONE, 
                    BlockBehaviour.Properties.ofFullCopy(ICE_ETHER_BLOCK.get()).noOcclusion()));

    // Вспомогательные методы регистрации
    private static <T extends Block> DeferredBlock<T> registerBlock(String name, Supplier<T> blockSupplier) {
        DeferredBlock<T> registeredBlock = BLOCKS.register(name, blockSupplier);
        registerBlockItem(name, registeredBlock);
        return registeredBlock;
    }

    private static <T extends Block> void registerBlockItem(String name, DeferredBlock<T> block) {
        ModItems.ITEMS.register(name, () -> new BlockItem(block.get(), new Item.Properties()));
    }

    public static void register(IEventBus eventBus) {
        BLOCKS.register(eventBus);
    }
}
```

## 4. Настройка DataGen

### 4.1. Таблицы лута блоков (`ModBlockLootTablesProvider`)
Некоторые блоки имеют особую логику выпадения:
* **Полублоки:** если два полублока объединены в полный блок, при разрушении должно выпасть **2** полублока (метод `createSlabItemTable`).
* **Двери:** дверь состоит из двух половинок (верхней и нижней), но при разрушении любой из них должен выпадать только **1** предмет двери (метод `createDoorTable`).

Откройте `ModBlockLootTablesProvider.java` и добавьте правила в метод `generate()`:

```java
@Override
protected void generate() {
    dropSelf(ModBlocks.ICE_ETHER_BLOCK.get());
    dropSelf(ModBlocks.RAW_ICE_ETHER_BLOCK.get());
    add(ModBlocks.ICE_ETHER_ORE.get(), block -> createCustomOreDrop(block, ModItems.RAW_ICE_ETHER.get(), 1.0f, 3.0f));

    // Обычные блоки выпадают сами
    dropSelf(ModBlocks.ICE_ETHER_STAIRS.get());
    dropSelf(ModBlocks.ICE_ETHER_BUTTON.get());
    dropSelf(ModBlocks.ICE_ETHER_PRESSURE_PLATE.get());
    dropSelf(ModBlocks.ICE_ETHER_FENCE.get());
    dropSelf(ModBlocks.ICE_ETHER_FENCE_GATE.get());
    dropSelf(ModBlocks.ICE_ETHER_WALL.get());
    dropSelf(ModBlocks.ICE_ETHER_TRAPDOOR.get());

    // Особые таблицы лута
    add(ModBlocks.ICE_ETHER_SLAB.get(), block -> createSlabItemTable(ModBlocks.ICE_ETHER_SLAB.get()));
    add(ModBlocks.ICE_ETHER_DOOR.get(), block -> createDoorTable(ModBlocks.ICE_ETHER_DOOR.get()));
}
```

### 4.2. Состояния и модели блоков (`ModBlockStateProvider`)

В `BlockStateProvider` уже есть готовые фабричные методы для генерации сложных состояний (`variants` и `multipart`).

Откройте `ModBlockStateProvider.java`:

```java
package com.besson.tutorial.datagen;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.block.ModBlocks;
import net.minecraft.data.PackOutput;
import net.minecraft.resources.ResourceLocation;
import net.neoforged.neoforge.client.model.generators.BlockStateProvider;
import net.neoforged.neoforge.common.data.ExistingFileHelper;

public class ModBlockStateProvider extends BlockStateProvider {

    public ModBlockStateProvider(PackOutput output, ExistingFileHelper existingFileHelper) {
        super(output, TutorialMod.MOD_ID, existingFileHelper);
    }

    @Override
    protected void registerStatesAndModels() {
        simpleBlockWithItem(ModBlocks.ICE_ETHER_BLOCK.get(), cubeAll(ModBlocks.ICE_ETHER_BLOCK.get()));
        simpleBlockWithItem(ModBlocks.RAW_ICE_ETHER_BLOCK.get(), cubeAll(ModBlocks.RAW_ICE_ETHER_BLOCK.get()));
        simpleBlockWithItem(ModBlocks.ICE_ETHER_ORE.get(), cubeAll(ModBlocks.ICE_ETHER_ORE.get()));

        // Базовая текстура исходного блока
        ResourceLocation texture = blockTexture(ModBlocks.ICE_ETHER_BLOCK.get());

        // 1. Ступени и Полублоки
        stairsBlock(ModBlocks.ICE_ETHER_STAIRS.get(), texture);
        slabBlock(ModBlocks.ICE_ETHER_SLAB.get(), texture, texture);

        // 2. Кнопка и Нажимная плита
        buttonBlock(ModBlocks.ICE_ETHER_BUTTON.get(), texture);
        pressurePlateBlock(ModBlocks.ICE_ETHER_PRESSURE_PLATE.get(), texture);

        // 3. Забор, Калитка и Стена
        fenceBlock(ModBlocks.ICE_ETHER_FENCE.get(), texture);
        fenceGateBlock(ModBlocks.ICE_ETHER_FENCE_GATE.get(), texture);
        wallBlock(ModBlocks.ICE_ETHER_WALL.get(), texture);

        // 4. Дверь и Люк с прозрачным слоем рендеринга ("cutout")
        doorBlockWithRenderType(ModBlocks.ICE_ETHER_DOOR.get(), 
                modLoc("block/ice_ether_door_bottom"), 
                modLoc("block/ice_ether_door_top"), 
                "cutout");

        trapdoorBlockWithRenderType(ModBlocks.ICE_ETHER_TRAPDOOR.get(), 
                modLoc("block/ice_ether_trapdoor"), 
                true, 
                "cutout");
    }
}
```

> 💡 **Слой `"cutout"`:**  
> Указывает видеокарте не смешивать полупрозрачные пиксели, а делать их полностью прозрачными (как у стекла или прутьев решетки). Это избавляет от черных рамок вокруг прозрачных участков текстуры двери.

### 4.3. Инвентарные 2D и 3D модели предметов (`models/item`)

Методы `fenceBlock`, `wallBlock` и `buttonBlock` генерируют модель блока в мире, но **не создают** корректную модель предмета для инвентаря. Дверь и вовсе должна выглядеть в руке как плоская 2D-иконка!

Добавим генерацию инвентарных моделей в `ModBlockStateProvider.java` (или через `ModItemModelProvider`):

```java
    // Добавьте вызовы этих методов в конец registerStatesAndModels():
    buttonInventory(ModBlocks.ICE_ETHER_BUTTON.getId().getPath(), texture);
    fenceInventory(ModBlocks.ICE_ETHER_FENCE.getId().getPath(), texture);
    wallInventory(ModBlocks.ICE_ETHER_WALL.getId().getPath(), texture);

    // Для полублока и ступеней модели предметов просто наследуют геометрию:
    itemModels().getBuilder(ModBlocks.ICE_ETHER_STAIRS.getId().getPath())
            .parent(itemModels().getExistingFile(modLoc("block/ice_ether_stairs")));
    itemModels().getBuilder(ModBlocks.ICE_ETHER_SLAB.getId().getPath())
            .parent(itemModels().getExistingFile(modLoc("block/ice_ether_slab")));
    itemModels().getBuilder(ModBlocks.ICE_ETHER_PRESSURE_PLATE.getId().getPath())
            .parent(itemModels().getExistingFile(modLoc("block/ice_ether_pressure_plate")));
    itemModels().getBuilder(ModBlocks.ICE_ETHER_FENCE_GATE.getId().getPath())
            .parent(itemModels().getExistingFile(modLoc("block/ice_ether_fence_gate")));
    itemModels().getBuilder(ModBlocks.ICE_ETHER_TRAPDOOR.getId().getPath())
            .parent(itemModels().getExistingFile(modLoc("block/ice_ether_trapdoor_bottom")));
```

А для плоской 2D-модели двери в `ModItemModelProvider.java`:
```java
// Дверь в инвентаре отображается как плоский предмет из текстуры item/ice_ether_door.png
basicItem(ModBlocks.ICE_ETHER_DOOR.asItem());
```

### 4.4. Теги соединения и инструментов (`ModBlockTagsProvider`)

Чтобы заборы соединялись между собой, калитки встраивались в проемы, а стены образовывали столбы, игра должна видеть их в соответствующих тегах:

Откройте `ModBlockTagsProvider.java`:

```java
@Override
protected void addTags(HolderLookup.Provider provider) {
    // 1. Все декоративные блоки добываются киркой
    tag(BlockTags.MINEABLE_WITH_PICKAXE)
            .add(ModBlocks.ICE_ETHER_BLOCK.get())
            .add(ModBlocks.RAW_ICE_ETHER_BLOCK.get())
            .add(ModBlocks.ICE_ETHER_ORE.get())
            .add(ModBlocks.ICE_ETHER_STAIRS.get())
            .add(ModBlocks.ICE_ETHER_SLAB.get())
            .add(ModBlocks.ICE_ETHER_BUTTON.get())
            .add(ModBlocks.ICE_ETHER_PRESSURE_PLATE.get())
            .add(ModBlocks.ICE_ETHER_FENCE.get())
            .add(ModBlocks.ICE_ETHER_FENCE_GATE.get())
            .add(ModBlocks.ICE_ETHER_WALL.get())
            .add(ModBlocks.ICE_ETHER_DOOR.get())
            .add(ModBlocks.ICE_ETHER_TRAPDOOR.get());

    // 2. Теги соединения геометрии
    tag(BlockTags.FENCES).add(ModBlocks.ICE_ETHER_FENCE.get());
    tag(BlockTags.FENCE_GATES).add(ModBlocks.ICE_ETHER_FENCE_GATE.get());
    tag(BlockTags.WALLS).add(ModBlocks.ICE_ETHER_WALL.get());
}
```

## 5. Тестирование в игре

1. Запустите конфигурацию **`Run Data`** — в консоли сгенерируются десятки сложных JSON-моделей и состояний.
2. Запустите клиент игры (**`Run Client`**).
3. Перейдите на вторую страницу творческого инвентаря во вкладку `Tutorial Tab`:
    * **Ступени и Полублоки:** проверьте установку в перевернутом положении (клик по верхней части блока) и соединение двух полублоков в целый блок.
    * **Забор и Стена:** поставьте заборы в ряд — благодаря тегу `BlockTags.FENCES` они корректно связываются между собой перекладинами.
    * **Дверь:** установите дверь на землю. Убедитесь, что сквозь прозрачные стеклянные вставки не просвечивает изнанка соседних блоков.
    * **Кнопка и Нажимная плита:** наступите на плиту или нажмите кнопку рядом с дверью — дверь откроется под действием сигнала редстоуна!
