# Урок 15: Создание гибридного инструмента (Киркотопор / Paxel) в NeoForge 1.21.1

В Уроке 14 мы создали стандартный набор из пяти раздельных инструментов. Однако одной из самых популярных механик в модах (например, *Mekanism* или *Modular Powersuits*) являются **мультиинструменты (Paxel / Paxcel)** — гибридные орудия, объединяющие функции сразу нескольких инструментов в одном предмете для экономии слотов инвентаря.

В этом уроке мы создадим **Киркотопор (Pickaxe-Axe)** из ледяного эфира:
* Работает одновременно и как **топор**, и как **кирка**.
* Добывает камень, руды, деревянные конструкции с высокой скоростью.
* Сохраняет уникальные функции ПКМ топора: обтесывание бревен (`Strip Log`), очистку окисленной меди (`Scrape`) и снятие воска (`Unwax`).
* Выбивает правильный лут из каменных блоков (исправим ошибку отсутствия дропа через систему тегов).

## 1. Теория: Архитектура мультиинструментов в Minecraft

### 1.1. Наследование: почему `AxeItem`, а не `Item`
Если бы мы создавали киркотопор прямым наследованием от `Item`, нам пришлось бы вручную копировать сотни строк кода взаимодействия топоров с миром (огромные таблицы маппинга обычных бревен в обтесанные, снятие стадий окисления с медных блоков, звуки строгания).

Вместо этого мы используем паттерн наследования:
```text
Item -> DiggerItem -> AxeItem -> PickaxeAxeItem
```
Унаследовав `AxeItem`, наш предмет автоматически получает все механики топора. Нам остается лишь расширить его возможности копания на блоки кирки.

---

### 1.2. Механика действий инструментов (`ItemAbilities` в NeoForge)
В NeoForge поведение инструментов описывается способностями **`ItemAbility`**:
* `ItemAbilities.AXE_STRIP` — снятие коры с бревен.
* `ItemAbilities.AXE_SCRAPE` — очистка окисленной меди.
* `ItemAbilities.AXE_WAX_OFF` — снятие воска.
* `ItemAbilities.PICKAXE_DIG` — разрушение камня и руд.

Переопределив метод `canPerformAction`, мы явно сообщаем игре, что предмет владеет способностями обоих классов.

## 2. Создание тега совместимости (`ModTags.Blocks`)

Чтобы определить, какие блоки наш гибрид копает с повышенной скоростью, объявим новый тег.

Откройте класс `ModTags.java` и добавьте константу в подкласс `Blocks`:

```java
public static class Blocks {
    public static final TagKey<Block> PROSPECTOR_ORES = tag("prospector_ores");

    // Тег блоков, которые быстро разрушаются киркотопором
    public static final TagKey<Block> PICKAXE_AXE_MINEABLE = tag("mineable/pickaxe_axe");

    private static TagKey<Block> tag(String name) {
        return TagKey.create(Registries.BLOCK, ResourceLocation.fromNamespaceAndPath(TutorialMod.MOD_ID, name));
    }
}
```

## 3. Создание класса `PickaxeAxeItem`

В пакете `com.besson.tutorial.item.custom` создайте класс `PickaxeAxeItem.java`:

```java
package com.besson.tutorial.item.custom;

import com.besson.tutorial.tag.ModTags;
import net.minecraft.world.item.AxeItem;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.Tier;
import net.minecraft.world.level.block.state.BlockState;
import net.neoforged.neoforge.common.ItemAbilities;
import net.neoforged.neoforge.common.ItemAbility;

public class PickaxeAxeItem extends AxeItem {

    public PickaxeAxeItem(Tier tier, Properties properties) {
        super(tier, properties);
    }

    /**
     * 1. Увеличение скорости разрушения для блоков из нашего тега
     */
    @Override
    public float getDestroySpeed(ItemStack stack, BlockState state) {
        // Если блок входит в объединенный тег киркотопора — копаем со скоростью тира (или 12.0f)
        if (state.is(ModTags.Blocks.PICKAXE_AXE_MINEABLE)) {
            return this.tier.getSpeed();
        }
        return super.getDestroySpeed(stack, state);
    }

    /**
     * 2. Разрешение выпадения лута (дропа) при разрушении каменных блоков
     */
    @Override
    public boolean isCorrectToolForDrops(ItemStack stack, BlockState state) {
        // Блок считается добываемым, если он в нашем теге и не превышает уровень тира
        return state.is(ModTags.Blocks.PICKAXE_AXE_MINEABLE)
                && !state.is(this.getTier().getIncorrectBlocksForDrops());
    }

    /**
     * 3. Поддержка действий и кирки, и топора для сторонних модов
     */
    @Override
    public boolean canPerformAction(ItemStack stack, ItemAbility itemAbility) {
        return ItemAbilities.DEFAULT_PICKAXE_ACTIONS.contains(itemAbility)
                || ItemAbilities.DEFAULT_AXE_ACTIONS.contains(itemAbility)
                || super.canPerformAction(stack, itemAbility);
    }
}
```

## 4. Регистрация киркотопора в `ModItems`

Откройте `ModItems.java`. Зарегистрируем новый инструмент со сбалансированными боевыми характеристиками (урон `+5.0f`, скорость атаки `-3.0f`):

```java
// ================= ГИБРИДНЫЕ ИНСТРУМЕНТЫ =================
public static final DeferredItem<PickaxeAxeItem> ICE_ETHER_PICKAXE_AXE = ITEMS.register(
        "ice_ether_pickaxe_axe",
        () -> new PickaxeAxeItem(ModToolTiers.ICE_ETHER, new Item.Properties()
                .attributes(PickaxeAxeItem.createAttributes(ModToolTiers.ICE_ETHER, 5.0f, -3.0f)))
);
```

## 6. Настройка DataGen

### 6.1. Объединение ванильных тегов в `ModBlockTagsProvider`
Самый изящный способ заставить киркотопор копать всё необходимое — это вложить два ванильных тега `mineable/pickaxe` и `mineable/axe` внутрь нашего кастомного тега через метод `.addTag(...)`!

Откройте `ModBlockTagsProvider.java`:

```java
@Override
protected void addTags(HolderLookup.Provider provider) {
    // Существующие регистрации...
    tag(BlockTags.MINEABLE_WITH_PICKAXE)
            .add(ModBlocks.ICE_ETHER_BLOCK.get())
            .add(ModBlocks.RAW_ICE_ETHER_BLOCK.get())
            .add(ModBlocks.ICE_ETHER_ORE.get());

    // ================= ТЕГ КИРКОТОПОРА =================
    // Включаем в наш тег абсолютно все блоки, которые ломаются киркой И топором
    tag(ModTags.Blocks.PICKAXE_AXE_MINEABLE)
            .addTag(BlockTags.MINEABLE_WITH_PICKAXE)
            .addTag(BlockTags.MINEABLE_WITH_AXE);
}
```

## 7. Разбор типичной ошибки: почему камень разрушается, но ничего не выпадает

В видео автор продемонстрировал классическую ловушку при создании мультиинструментов:
1. Если переопределить только метод `getDestroySpeed`, камень начнет ломаться визуально быстро.
2. Но в режиме выживания после разрушения камня или угольной руды **выпадение предметов не произойдет**!
3. **Причина:** В Minecraft за дроп отвечает не скорость копания, а проверка `isCorrectToolForDrops`. Поскольку базовый класс `AxeItem` знает только про дерево, он считает, что камень сломан «неподходящим инструментом» (как кулаком), и уничтожает лут.
4. **Решение:** Обязательное переопределение метода `isCorrectToolForDrops` в классе предмета и связывание тегов в `ModBlockTagsProvider`.

## 8. Тестирование в игре

1. Запустите генерацию ресурсов через конфигурацию **`Run Data`**.
2. Запустите клиент (**`Run Client`**).
3. Войдите в мир и переключитесь в режим выживания (`/gamemode survival`).
4. **Тест топора:**
    * Подойдите к дереву: древесина срубается мгновенно.
    * Нажмите ПКМ по стволу: кора успешно снимается, превращая бревно в обтесанное.
5. **Тест кирки:**
    * Спуститесь в шахту: камень разрушается с высокой скоростью ($12.0f$).
    * Из камня выпадает булыжник, из угольной руды — уголь, из руды ледяного эфира — кристаллы эфира.
6. **Тест боя:**
    * Нанесите удар зомби: оружие наносит высокий урон с задержкой замаха, присущей тяжелому оружию.
