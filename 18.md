# Урок 18: Сет-эффекты брони (Armor Set Effects) в NeoForge 1.21.1

В Уроке 17 мы создали и зарегистрировали стандартный комплект брони из ледяного эфира. Однако в большинстве современных RPG и приключенческих модификаций полный комплект брони дает игроку уникальные пассивные способности — **сет-эффекты (Full Set Effects)**.

В этом уроке мы реализуем механику комплектных бонусов:
* Когда игрок надевает **все 4 элемента** брони из ледяного эфира (шлем, нагрудник, поножи и ботинки), на него автоматически накладываются эффекты зелий: **«Скорость II»** и **«Прыгучесть II»**.
* Если игрок снимает хотя бы одну деталь (или она ломается в бою), эффект немедленно прекращается.
* Разберем механику `inventoryTick` и методы оптимизации, чтобы постоянная проверка брони не перегружала главный поток сервера.
* Добавим защиту от вылета игры при надевании элитр вместо нагрудника.

## 1. Теория: Механика отслеживания брони в реальном времени

### 1.1. Метод `inventoryTick` и частота вызовов
В базовом классе `net.minecraft.world.item.Item` есть виртуальный метод:
```java
public void inventoryTick(ItemStack stack, Level level, Entity entity, int slotId, boolean isSelected)
```
Этот метод вызывается игрой **каждый игровой тик (20 раз в секунду)** для каждого предмета, находящегося в инвентаре игрока, включая надетое снаряжение.

> ⚠️ **Предостережение о производительности:**  
> Поскольку метод выполняется 20 раз в секунду для каждого надетго элемента (суммарно $20 \times 4 = 80$ раз в секунду только на одного игрока), здесь **категорически запрещено** выполнять ресурсоемкие операции (поиск путей, сложные циклы обхода мира, обращение к базам данных). Все проверки должны сводиться к быстрым сравнениям ссылок в памяти.

---

### 1.2. Настройка `MobEffectInstance`
Для гибкой настройки эффекта используется полный конструктор `MobEffectInstance`:
```java
new MobEffectInstance(
    Holder<MobEffect> effect, // Сам эффект (Скорость, Прыгучесть и т.д.)
    int duration,             // Длительность в тиках
    int amplifier,            // Уровень эффекта (0 = I уровень, 1 = II уровень)
    boolean ambient,          // true, если эффект от маяка/проводника (бледные частицы)
    boolean visible,          // Видимость летающих вокруг игрока спиралей частиц
    boolean showIcon          // Отображение иконки в правом верхнем углу интерфейса
)
```

Для пассивного бонуса от брони летающие цветные пузыри зелий на экране только мешают обзору. Поэтому параметр `visible` устанавливается в `false`, а `showIcon` — в `true`.

## 2. Создание класса `ModArmorItem`

В пакете `com.besson.tutorial.item.custom` создайте класс `ModArmorItem.java`. Он будет наследоваться от ванильного `ArmorItem`.

```java
package com.besson.tutorial.item.custom;

import com.besson.tutorial.item.ModArmorMaterials;
import com.google.common.collect.ImmutableMap;
import net.minecraft.core.Holder;
import net.minecraft.world.effect.MobEffectInstance;
import net.minecraft.world.effect.MobEffects;
import net.minecraft.world.entity.Entity;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.item.ArmorItem;
import net.minecraft.world.item.ArmorMaterial;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.level.Level;

import java.util.List;
import java.util.Map;

public class ModArmorItem extends ArmorItem {

    // 1. Карта соответствия: Материал брони -> Список выдаваемых статус-эффектов
    private static final Map<Holder<ArmorMaterial>, List<MobEffectInstance>> MATERIAL_TO_EFFECT_MAP =
            new ImmutableMap.Builder<Holder<ArmorMaterial>, List<MobEffectInstance>>()
                    .put(ModArmorMaterials.ICE_ETHER, List.of(
                            // Скорость II на 10 секунд (200 тиков), без назойливых частиц
                            new MobEffectInstance(MobEffects.MOVEMENT_SPEED, 200, 1, false, false, true),
                            // Прыгучесть II на 10 секунд (200 тиков)
                            new MobEffectInstance(MobEffects.JUMP, 200, 1, false, false, true)
                    ))
                    .build();

    public ModArmorItem(Holder<ArmorMaterial> material, Type type, Properties properties) {
        super(material, type, properties);
    }

    @Override
    public void inventoryTick(ItemStack stack, Level level, Entity entity, int slotId, boolean isSelected) {
        // Проверку выполняем строго на стороне сервера и только для сущности игрока
        if (!level.isClientSide() && entity instanceof Player player) {
            // Проверяем, надеты ли все 4 слота брони
            if (hasFullSuitOfArmorOn(player)) {
                evaluateArmorEffects(player);
            }
        }
        super.inventoryTick(stack, level, entity, slotId, isSelected);
    }
```

### 2.2. Порядок слотов брони в инвентаре
В структуре инвентаря игрока `player.getInventory().getArmor(slot)` слоты брони проиндексированы **снизу вверх**:
* `slot = 0` — **Ботинки (Boots)**
* `slot = 1` — **Поножи (Leggings)**
* `slot = 2` — **Нагрудник (Chestplate)**
* `slot = 3` — **Шлем (Helmet)**

---

### 2.3. Защита от элитр и валидация полного сета
Если игрок наденет элитры, в слоте нагрудника окажется предмет, который **не является** `ArmorItem`. Попытка прямого приведения типов `(ArmorItem) stack.getItem()` мгновенно приведет к ошибке `ClassCastException` и падению сервера.

Добавим безопасные вспомогательные методы в класс `ModArmorItem`:

```java
    /**
     * Проверяет, что все 4 слота брони не пусты
     */
    private boolean hasFullSuitOfArmorOn(Player player) {
        ItemStack boots = player.getInventory().getArmor(0);
        ItemStack leggings = player.getInventory().getArmor(1);
        ItemStack chestplate = player.getInventory().getArmor(2);
        ItemStack helmet = player.getInventory().getArmor(3);

        return !boots.isEmpty() && !leggings.isEmpty() && !chestplate.isEmpty() && !helmet.isEmpty();
    }

    /**
     * Проверяет, что все 4 предмета брони сделаны из одного и того же материала
     */
    private boolean hasCorrectArmorOn(Holder<ArmorMaterial> material, Player player) {
        for (int i = 0; i < 4; i++) {
            ItemStack armorStack = player.getInventory().getArmor(i);

            // ЗАЩИТА: проверяем, что предмет действительно является броней (а не элитрами или черепом)
            if (!(armorStack.getItem() instanceof ArmorItem armorItem)) {
                return false;
            }

            // Проверяем совпадение материала
            if (!armorItem.getMaterial().equals(material)) {
                return false;
            }
        }
        return true;
    }
```

## 3. Реализация логики наложения эффектов

Теперь свяжем проверку сета с добавлением эффектов:

```java
    /**
     * Оценка брони и наложение соответствующих бонусов
     */
    private void evaluateArmorEffects(Player player) {
        for (Map.Entry<Holder<ArmorMaterial>, List<MobEffectInstance>> entry : MATERIAL_TO_EFFECT_MAP.entrySet()) {
            Holder<ArmorMaterial> material = entry.getKey();
            List<MobEffectInstance> effects = entry.getValue();

            if (hasCorrectArmorOn(material, player)) {
                addArmorEffects(player, effects);
            }
        }
    }

    /**
     * Добавление эффектов игроку, если они еще не активны
     */
    private void addArmorEffects(Player player, List<MobEffectInstance> effects) {
        for (MobEffectInstance effect : effects) {
            // Если у игрока еще нет эффекта или он почти закончился — обновляем его
            boolean hasEffect = player.hasEffect(effect.getEffect());

            if (!hasEffect) {
                // Создаем копию эффекта, чтобы не мутировать исходный шаблон
                player.addEffect(new MobEffectInstance(
                        effect.getEffect(),
                        effect.getDuration(),
                        effect.getAmplifier(),
                        effect.isAmbient(),
                        effect.isVisible(),
                        effect.showIcon()
                ));
            }
        }
    }
}
```

> 💡 **Как работает снятие эффекта:**  
> Мы накладываем эффект с короткой продолжительностью в 200 тиков (10 секунд). Пока на игроке надет полный комплект, метод `inventoryTick` непрерывно поддерживает действие эффекта. Как только игрок снимает хотя бы одну деталь, обновление прекращается, и эффект исчезает.

## 4. Обновление регистрации предметов в `ModItems`

```java
// ================= БРОНЯ (С поддержкой сет-эффектов) =================

        "ice_ether_helmet",
        () -> new ModArmorItem(ModArmorMaterials.ICE_ETHER, ArmorItem.Type.HELMET,
```

## 5. Тестирование в игре

1. Запустите клиент игры через конфигурацию **`Run Client`**.
2. Создайте или откройте тестовый мир.
3. Возьмите полный комплект эфирной брони:
    * **Тест 1 (Неполный комплект):**
        * Наденьте шлем, поножи и ботинки, оставив слот нагрудника пустым.
        * Убедитесь, что никаких эффектов на персонаже **нет**.
    * **Тест 2 (Активация сета):**
        * Наденьте нагрудник: в правом верхнем углу экрана мгновенно появятся иконки **«Скорость II»** и **«Прыгучесть II»**.
        * Персонаж начнет бегать значительно быстрее и перепрыгивать препятствия высотой в 2 блока.
        * Обратите внимание: вокруг персонажа нет мешающих спиралей зелий, так как параметр `visible` выключен.
    * **Тест 3 (Снятие снаряжения):**
        * Снимите ботинки — через несколько секунд эффекты плавно иссякнут.
        * Снова наденьте ботинки — эффекты моментально возобновятся.
    * **Тест 4 (Проверка на краш с элитрами):**
        * Наденьте шлем, поножи, ботинки и ванильные элитры (`Elytra`).
        * Убедитесь, что игра работает стабильно, сервер не выдает ошибок в консоль, а логика корректно распознает, что комплект не собран.
