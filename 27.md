# Урок 27: Соединяемый диван: блок с состояниями `FACING` и `TYPE` (Sofa) в NeoForge 1.21.1

В прошлом уроке мы научили блок поворачиваться к игроку. Теперь усложним задачу и сделаем **диван**, который **сам соединяется с соседними диванами** в длинный ряд: у него есть левый край, середина, правый край и одиночный вариант, а сам блок при этом поворачивается в четыре стороны света.

В этом уроке мы:
* подготовим **четыре модели** дивана (одиночный, левый, средний, правый);
* создадим **перечисление `Type`** и подключим его как свойство блока (`EnumProperty`);
* напишем **логику соединения** блоков через `updateShape` и разберёмся, как определить «левого» и «правого» соседа с помощью `getCounterClockWise()` и `getClockWise()`;
* сгенерируем состояния блока через DataGen «вручную» (`getVariantBuilder`), потому что готовый `horizontalBlock(...)` из Урока 26 нам больше не подходит.

Логику, которая позволяет на диван **садиться**, мы реализуем в следующем уроке. Пока диван только соединяется.

> 💡 **Что нужно знать заранее.** Урок опирается на Урок 26 (свойство `FACING`, `getStateForPlacement`, `rotate`, `mirror`, `createBlockStateDefinition`), Урок 25 (кастомные модели из Blockbench, пути к текстурам) и Урок 7 (DataGen).

## 1. Подготовка моделей

Диван — это **соединяемый блок**. Чтобы он красиво выглядел в ряду, нам нужны четыре отдельные модели:

| Состояние (`type`) | Файл модели | Когда используется |
| :--- | :--- | :--- |
| `single` | `sofa.json` | Диван без соседей. Эта же модель показывается **в инвентаре** |
| `left` | `sofa_left.json` | Левый край ряда |
| `middle` | `sofa_middle.json` | Середина ряда |
| `right` | `sofa_right.json` | Правый край ряда |

Что важно помнить при создании:
* **Display-настройки** (положение в руке, в инвентаре, на земле) достаточно настроить только у **одиночной модели** `sofa`, потому что именно она отображается как предмет. Остальные три можно не настраивать.
* Как и раньше, **лицевая сторона** модели (то, куда смотрит сиденье) должна смотреть на **север** (грань North). Эта сторона нужна для поворотов через `rotationY` (см. Урок 26).
* Каждую модель экспортируйте через **File → Export → Export Block/Item Model**, а текстуру сохраняйте в PNG.
* Если вы хорошо продумаете развёртку, все четыре модели смогут использовать **одну общую текстуру**. В видеоуроке для простоты у каждой модели своя текстура.

Готовые модели можно также взять в репозитории автора курса.

> 💡 **Положите модели и текстуры в проект сразу.** Так вы не забудете о них, когда дойдёте до DataGen: если модели не будет, `getExistingFile` не найдёт её, и генерация завершится ошибкой.

```text
src/main/resources/assets/tutorial_mod/
├── models/
│   └── block/
│       ├── sofa.json
│       ├── sofa_left.json
│       ├── sofa_middle.json
│       └── sofa_right.json
└── textures/
    └── block/
        ├── sofa.png
        ├── sofa_left.png
        ├── sofa_middle.png
        └── sofa_right.png
```

Не забудьте исправить пути к текстурам внутри каждого JSON (допишите `tutorial_mod:`), как в разделе 9.1 Урока 25.

## 2. Перечисление `Type`

Состояние соединения диван хранит в **свойстве-перечислении**. Создайте класс `SofaBlock` в пакете `com.besson.tutorial.block.custom` (наследуем от обычного `Block`) и сразу добавьте в него вложенное перечисление `Type`:

```java
public enum Type implements StringRepresentable {
    SINGLE("single"),
    LEFT("left"),
    MIDDLE("middle"),
    RIGHT("right");

    private final String name;

    Type(String name) {
        this.name = name;
    }

    @Override
    public String getSerializedName() {
        return name;
    }
}
```

Разберём:
* `StringRepresentable` — интерфейс, который требует Minecraft от перечислений, используемых как свойства блока. Метод `getSerializedName()` возвращает **строку для blockstate JSON** (`type=left`, `type=middle` и так далее).
* Четыре значения соответствуют четырём моделям из предыдущего раздела.

> 💡 Это не первое перечисление, которое мы подключаем к блоку: готовые свойства-перечисления есть и у ванили (посмотрите `BlockStateProperties`). Своё перечисление мы оформляем как **внутренний класс** блока, потому что нигде больше оно не пригодится.

## 3. Свойства блока и базовые методы

Добавьте в `SofaBlock` два свойства:

```java
public static final DirectionProperty FACING = BlockStateProperties.HORIZONTAL_FACING;
public static final EnumProperty<Type> TYPE = EnumProperty.create("type", Type.class);
```

* `FACING` — горизонтальное направление, как в Уроке 26.
* `TYPE` — наше перечисление. Первый аргумент `"type"` — имя свойства в blockstate JSON.

Теперь конструктор. В нём задаём **состояние по умолчанию**: диван смотрит на север и является одиночным.

```java
public SofaBlock(Properties properties) {
    super(properties);
    this.registerDefaultState(this.stateDefinition.any()
            .setValue(FACING, Direction.NORTH)
            .setValue(TYPE, Type.SINGLE));
}
```

Методы, связанные с направлением, **такие же, как у `SimpleOrangeClock`** в Уроке 26 — их можно скопировать оттуда:

```java
@Override
protected BlockState rotate(BlockState state, Rotation rotation) {
    return state.setValue(FACING, rotation.rotate(state.getValue(FACING)));
}

@Override
protected BlockState mirror(BlockState state, Mirror mirror) {
    return state.rotate(mirror.getRotation(state.getValue(FACING)));
}

@Nullable
@Override
public BlockState getStateForPlacement(BlockPlaceContext context) {
    return this.defaultBlockState()
            .setValue(FACING, context.getHorizontalDirection().getOpposite());
}
```

Единственное отличие — в `createBlockStateDefinition` теперь нужно зарегистрировать **оба** свойства:

```java
@Override
protected void createBlockStateDefinition(StateDefinition.Builder<Block, BlockState> builder) {
    builder.add(FACING, TYPE);
}
```

## 4. Логика соединения блоков

Теперь самое интересное: диван должен сам определять, есть ли у него соседи слева и справа.

### 4.1. Метод `updateShape`

Переопределите метод `updateShape`:

```java
@Override
protected BlockState updateShape(BlockState state, Direction direction, BlockState neighborState,
                                 LevelAccessor level, BlockPos pos, BlockPos neighborPos) {
    return getRelatedBlockState(state, level, pos, state.getValue(FACING));
}
```

Игра вызывает `updateShape` у блока всякий раз, когда **рядом с ним что-то меняется**: соседний блок поставили или сломали. Метод возвращает **новое состояние** блока. Мы пользуемся этим, чтобы пересчитать тип дивана (одиночный, левый, средний, правый). Сам метод пересчёта `getRelatedBlockState` напишем ниже.

### 4.2. Метод `getRelatedBlockState`

```java
private BlockState getRelatedBlockState(BlockState state, LevelAccessor level, BlockPos pos, Direction value) {
    boolean left = isRelatedBlock(level, pos, value, true);
    boolean right = isRelatedBlock(level, pos, value, false);

    if (left && right) {
        return state.setValue(TYPE, Type.MIDDLE);
    } else if (left) {
        return state.setValue(TYPE, Type.RIGHT);
    } else if (right) {
        return state.setValue(TYPE, Type.LEFT);
    }
    return state.setValue(TYPE, Type.SINGLE);
}
```

Логика такая:

| Сосед слева | Сосед справа | Результат |
| :---: | :---: | :--- |
| да | да | `MIDDLE` (середина) |
| да | нет | `RIGHT` (правый край: слева продолжение, справа конец) |
| нет | да | `LEFT` (левый край) |
| нет | нет | `SINGLE` (одиночный) |

### 4.3. Метод `isRelatedBlock`: кто «слева», а кто «справа»

Последний метод проверяет, есть ли на нужной стороне **такой же диван, смотрящий в ту же сторону**:

```java
private boolean isRelatedBlock(LevelAccessor level, BlockPos pos, Direction value, boolean counterClockwise) {
    Direction rotate = counterClockwise ? value.getCounterClockWise() : value.getClockWise();
    BlockState state = level.getBlockState(pos.relative(rotate));
    if (state.getBlock() == this) {
        Direction direction = state.getValue(FACING);
        return direction.equals(value);
    }
    return false;
}
```

Разберём подробнее, потому что именно здесь кроется вся логика.

**`getCounterClockWise()` и `getClockWise()`.** Эти методы `Direction` поворачивают направление на 90° против или по часовой стрелке (если смотреть сверху). Для горизонтальных направлений получается такая таблица:

| Диван смотрит (`facing`) | Слева (против часовой) | Справа (по часовой) |
| :---: | :---: | :---: |
| `north` | `west` | `east` |
| `east` | `north` | `south` |
| `south` | `east` | `west` |
| `west` | `south` | `north` |

Проще всего представить так: вы стоите лицом в сторону, куда смотрит диван (то есть сидите на нём). Тогда слева от вас находится сторона, получаемая поворотом **против часовой стрелки**, а справа — **по часовой**. Например, диван смотрит на запад: слева от сидящего юг, справа север.

> 💡 **Проверка в Blockbench.** Нарисуйте на кубе букву «N» на северной грани и поверните модель против часовой стрелки: север станет западом. Это ровно та же операция, что делает `getCounterClockWise()`.

**`pos.relative(rotate)`** сдвигает позицию на один блок в указанную сторону. Таким образом, мы берём **соседний блок** слева или справа.

**Проверка соседа.** Мы выясняем, что (1) это **такой же блок** (`state.getBlock() == this`) и (2) он смотрит в **ту же сторону**, что и наш (`direction.equals(value)`). Второе условие нужно, чтобы диваны с разным направлением (один на юг, другой на север) не соединялись: это выглядело бы странно.

> 💡 **Куда расширять.** В реальной жизни у диванов бывают угловые модели. Можно реализовать соединение на углах так же, как у лестниц (отдельные типы и модели для внутреннего и внешнего угла). Эту задачу оставляем вам.

> 💡 **Совет по надёжности.** Диван пересчитывает тип, когда меняется сосед. Чтобы новый блок получал корректный тип сразу при установке (а не после обновления соседей), можно вызвать пересчёт ещё и в `getStateForPlacement`:
> ```java
> Direction facing = context.getHorizontalDirection().getOpposite();
> return getRelatedBlockState(this.defaultBlockState().setValue(FACING, facing),
>         context.getLevel(), context.getClickedPos(), facing);
> ```
> Так делают, например, лестницы. В видеоуроке это не используется, и ряд соединяется и так.

## 5. Регистрация блока, креативная вкладка, лут и переводы

В `ModBlocks.java`:

```java
public static final DeferredBlock<Block> SOFA = registerBlock("sofa",
        () -> new SofaBlock(BlockBehaviour.Properties.of()
                .strength(2.0F, 3.0F)
                .noOcclusion()));
```

> 💡 `.noOcclusion()` нужен, если модель не заполняет весь куб (см. Урок 25). Хитбокс дивана мы сейчас не настраиваем: он остаётся полным кубом. При желании настройте его по методике из Урока 26.

Креативная вкладка (`ModCreativeModeTabs`):


```java

```

Переводы:

```java

// ModRuRuLangProvider
```

## 6. DataGen: состояния блока для 16 вариантов

С моделями диван устроен сложнее, чем часы из Урока 26: у него два свойства, поэтому у блока **4 направления × 4 типа = 16 состояний**. Готовый метод `horizontalBlock(...)` умеет работать только с направлением, поэтому здесь нужно собрать состояния вручную через `getVariantBuilder(...)`.

Откройте `ModBlockStateProvider.java` и добавьте метод:

```java
private <T extends Block> void sofaBlockWithModels(DeferredBlock<T> sofa) {
    String name = sofa.getId().getPath();

    ModelFile single = models().getExistingFile(modLoc("block/" + name));
    ModelFile left   = models().getExistingFile(modLoc("block/" + name + "_left"));
    ModelFile middle = models().getExistingFile(modLoc("block/" + name + "_middle"));
    ModelFile right  = models().getExistingFile(modLoc("block/" + name + "_right"));

    getVariantBuilder(sofa.get()).forAllStates(state -> {
        SofaBlock.Type type = state.getValue(SofaBlock.TYPE);
        Direction facing = state.getValue(SofaBlock.FACING);

        // Какую модель брать для данного типа
        ModelFile model = switch (type) {
            case LEFT -> left;
            case MIDDLE -> middle;
            case RIGHT -> right;
            default -> single;
        };

        // На сколько градусов повернуть модель
        int yRotation = switch (facing) {
            case EAST -> 90;
            case SOUTH -> 180;
            case WEST -> 270;
            default -> 0;
        };

        return ConfiguredModel.builder()
                .modelFile(model)
                .rotationY(yRotation)
                .build();
    });

    // Предмет в инвентаре использует одиночную модель
    simpleBlockItem(sofa.get(), single);
}
```

Разберём:
* Первые четыре строки берут **готовые файлы моделей** по имени блока: `sofa`, `sofa_left`, `sofa_middle`, `sofa_right`. Поэтому файлы моделей должны быть названы именно так.
* `getVariantBuilder(...).forAllStates(...)` вызывает наш код **для каждого из 16 состояний** и просит вернуть модель с поворотом.
* Первый `switch` выбирает модель по `type`, второй — угол поворота по `facing`. Углы те же, что делает `horizontalBlock`: восток 90°, юг 180°, запад 270°, север без поворота.
* `simpleBlockItem(...)` вручную добавляет модель предмета: в инвентаре диван выглядит как **одиночная** модель.

Вызовите метод в `registerStatesAndModels()`:

```java
sofaBlockWithModels(ModBlocks.SOFA);
```

Запустите **`Run Data`**. В сгенерированном `blockstates/sofa.json` вы увидите, что у состояний теперь по два параметра, например `facing=north,type=left`. У часов из Урока 26 был только `facing`, а у дивана появился ещё и `type`, поэтому вариантов стало больше.

## 7. Тестирование в игре

1. Запустите **`Run Data`**, затем **`Run Client`**.
2. Получите диван из креативной вкладки.
3. Поставьте несколько диванов подряд. Ряд должен соединяться: на краях появляются левый и правый варианты, посередине — средний. Длина ряда не ограничена.
4. Поставьте диваны, повернувшись в **разные стороны света**: каждый ряд должен повернуться вместе с вами.
5. Поставьте диван рядом с диваном, смотрящим в другую сторону: они **не** должны соединяться.
6. Сломайте средний диван: соседние должны превратиться в края ряда.

Пока на диване нельзя сидеть: клик правой кнопкой ничего не делает, а на диван можно просто поставить блок сверху. Механику посадки мы реализуем в следующем уроке.

## 8. Частые ошибки

* **Диван не соединяется.** Не переопределён `updateShape`, или в `createBlockStateDefinition` забыли `TYPE`.
* **Диван соединяется «наоборот»: левый край оказывается справа.** Перепутаны `true`/`false` в вызовах `isRelatedBlock` либо порядок `LEFT`/`RIGHT` в `getRelatedBlockState`. Сверьтесь с таблицами из раздела 4.
* **Диваны с разным направлением соединяются.** В `isRelatedBlock` пропущена проверка `direction.equals(value)`.
* **DataGen падает с ошибкой «файл модели не найден».** Одной из четырёх моделей нет в `assets/tutorial_mod/models/block/` или она названа иначе (`sofa_left`, `sofa_middle`, `sofa_right`).
* **В инвентаре диван выглядит неправильно.** Нет `simpleBlockItem(...)` или не настроены Display-слоты у одиночной модели `sofa`.
* **Чёрно-фиолетовые модели.** В JSON не указано пространство имён `tutorial_mod:` у текстур либо текстуры лежат не в `textures/block`.
* **Диван смотрит не на игрока.** Забыли `.getOpposite()` в `getStateForPlacement` или лицевая сторона модели в Blockbench смотрит не на север.
* **Сквозь диван видно мир.** Забыли `.noOcclusion()` в свойствах блока.

***

В следующем уроке мы научим диван принимать сидящего игрока.
