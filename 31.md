# Урок 31: Создание колонн с вертикальным соединением (Pillar / Column Block) в NeoForge 1.21.1

В архитектурных и декоративных модификациях важную роль играют так называемые **«умные» соединяемые блоки**. В отличие от обычных кубов, они динамически меняют свой внешний вид в зависимости от того, какие блоки расположены рядом.

В Уроке 27 мы разбирали горизонтальное соединение диванов. В этом уроке мы создадим блок с **вертикальным соединением — Архитектурную колонну из ледяного эфира (`Ice Ether Pillar`)**:
* Разберем принцип классической ордерной архитектуры: база (основание), тело (стержень колонны) и капитель (верхушка).
* Создадим собственное перечисление **`PillarType`** с 4 состояниями (`SINGLE`, `BOTTOM`, `MIDDLE`, `TOP`), реализующее интерфейс `StringRepresentable`.
* Напишем логику проверки соседей по вертикали в методах **`getStateForPlacement`** и **`updateShape`**.
* Узнаем, как блоки автоматически реагируют на установку и разрушение соседних блоков выше и ниже.
* Настроим DataGen: сгенерируем комплексный BlockState сразу под 4 модели и разберем распространенную ошибку с отсутствием модели предмета в инвентаре.

## 1. Теория: Принцип вертикального соединения блоков

### 1.1. Четыре состояния колонны
В отличие от обычного бревна или базальтового столба, которые просто поворачиваются по осям X/Y/Z, архитектурная колонна должна визуально адаптироваться к своей высоте:
1. **`SINGLE` (Одиночная):** над колонной и под ней нет таких же блоков. Отображает и базу, и капитель одновременно.
2. **`BOTTOM` (Нижняя / База):** блок имеет соседа сверху, но не имеет снизу. Имеет широкое массивное основание.
3. **`MIDDLE` (Средняя / Тело колонны):** есть соседи и сверху, и снизу. Представляет собой гладкий цилиндрический стержень без выступов.
4. **`TOP` (Верхняя / Капитель):** есть сосед снизу, но нет сверху. Венчается декоративным карнизом или узором.

```
       [Одиночный]               [Составная колонна]

       +---------+  TOP          +---------+ (Капитель)
       | SINGLE  |               |   TOP   |
       +---------+               +---------+
                                 | MIDDLE  | (Стержень)
                                 +---------+
                                 | MIDDLE  | (Стержень)
                                 +---------+
                    BOTTOM       | BOTTOM  | (База)
                                 +---------+
```

---

### 1.2. Роль интерфейса `StringRepresentable` и `EnumProperty`
В Minecraft свойства блока могут быть числовыми (`IntegerProperty`), логическими (`BooleanProperty`) или вариантными (`EnumProperty`).

Чтобы использовать Java-перечисление в качестве свойства блокстейта, `enum` **обязан реализовать интерфейс `StringRepresentable`** и вернуть уникальную текстовую строку в методе `getSerializedName()`:
* Имя должно содержать **только строчные буквы** английского алфавита (`a-z`, цифры, `_`).
* Это имя напрямую записывается в BlockState JSON (`"type=bottom"`, `"type=middle"` и т.д.).

---

### 1.3. Методы `getStateForPlacement` и `updateShape`
1. **`getStateForPlacement(BlockPlaceContext context)`:**  
   Вызывается **в момент установки блока**. Проверяет окружение и сразу задает правильную модель, избавляя игрока от мерцания текстуры.
2. **`updateShape(BlockState state, Direction direction, ...)`:**  
   Вызывается движком **каждый раз, когда соседний блок меняется, устанавливается или разрушается**. Если изменение произошло строго по вертикали (`Direction.UP` или `Direction.DOWN`), блок мгновенно пересчитывает свое состояние.

## 2. Создание перечисления состояний `PillarType`

1. В пакете вашего мода создайте подпакет `block.custom.properties` (или поместите в `block.custom`).
2. Создайте `enum PillarType.java`:

```java
package com.besson.tutorial.block.custom.properties;

import net.minecraft.util.StringRepresentable;

public enum PillarType implements StringRepresentable {
    SINGLE("single"),   // Одиночный блок (с основанием и верхушкой)
    BOTTOM("bottom"),   // Нижний блок (основание колонны)
    MIDDLE("middle"),   // Средняя секция (гладкий стержень)
    TOP("top");         // Верхний блок (капитель)

    private final String name;

    PillarType(String name) {
        this.name = name;
    }

    @Override
    public String getSerializedName() {
        return this.name;
    }

    @Override
    public String toString() {
        return this.name;
    }
}
```

> ⚠️ **Предостережение от автора урока:**  
> Не используйте в названиях констант перечисления заглавные буквы или спецсимволы в методе `getSerializedName()`. Только строчный латинский регистр, иначе игра упадет с ошибкой валидации реестра блокстейтов при запуске!

## 3. Создание класса колонны `PillarBlock`

В пакете `com.besson.tutorial.block.custom` создайте класс `PillarBlock.java`:

```java
package com.besson.tutorial.block.custom;

import com.besson.tutorial.block.custom.properties.PillarType;
import net.minecraft.core.BlockPos;
import net.minecraft.core.Direction;
import net.minecraft.world.item.context.BlockPlaceContext;
import net.minecraft.world.level.BlockGetter;
import net.minecraft.world.level.LevelAccessor;
import net.minecraft.world.level.LevelReader;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.state.BlockState;
import net.minecraft.world.level.block.state.StateDefinition;
import net.minecraft.world.level.block.state.properties.EnumProperty;
import net.minecraft.world.phys.shapes.CollisionContext;
import net.minecraft.world.phys.shapes.VoxelShape;

public class PillarBlock extends Block {

    // 1. Регистрируем свойство перечисления TYPE
    public static final EnumProperty<PillarType> TYPE = EnumProperty.create("type", PillarType.class);

    // Хитбокс колонны: слегка уже полного куба (отступ по 2 пикселя с каждой стороны)
    protected static final VoxelShape SHAPE = Block.box(2.0, 0.0, 2.0, 14.0, 16.0, 14.0);

    public PillarBlock(Properties properties) {
        super(properties);
        // По умолчанию блок устанавливается как одиночный
        this.registerDefaultState(this.stateDefinition.any().setValue(TYPE, PillarType.SINGLE));
    }

    @Override
    public VoxelShape getShape(BlockState state, BlockGetter level, BlockPos pos, CollisionContext context) {
        return SHAPE;
    }

    // ================= ЛОГИКА ВЕРТИКАЛЬНОГО СОЕДИНЕНИЯ =================

    /**
     * Вычисление типа блока в зависимости от блоков сверху и снизу
     */
    private BlockState updatePillarState(BlockState state, LevelReader level, BlockPos pos) {
        boolean hasAbove = level.getBlockState(pos.above()).is(this);
        boolean hasBelow = level.getBlockState(pos.below()).is(this);

        if (hasAbove && hasBelow) {
            return state.setValue(TYPE, PillarType.MIDDLE);
        } else if (hasAbove) {
            return state.setValue(TYPE, PillarType.BOTTOM);
        } else if (hasBelow) {
            return state.setValue(TYPE, PillarType.TOP);
        } else {
            return state.setValue(TYPE, PillarType.SINGLE);
        }
    }

    /**
     * Определение состояния при установке блока игроком
     */
    @Override
    public BlockState getStateForPlacement(BlockPlaceContext context) {
        return updatePillarState(this.defaultBlockState(), context.getLevel(), context.getClickedPos());
    }

    /**
     * Динамическое обновление при изменении соседей
     */
    @Override
    public BlockState updateShape(BlockState state, Direction direction, BlockState neighborState, 
                                  LevelAccessor level, BlockPos pos, BlockPos neighborPos) {
        // Если изменился блок строго сверху или строго снизу — пересчитываем форму
        if (direction.getAxis().isVertical()) {
            return updatePillarState(state, level, pos);
        }
        return super.updateShape(state, direction, neighborState, level, pos, neighborPos);
    }

    @Override
    protected void createBlockStateDefinition(StateDefinition.Builder<Block, BlockState> builder) {
        builder.add(TYPE);
    }
}
```

## 4. Регистрация блока в `ModBlocks`

Откройте класс `ModBlocks.java` и зарегистрируйте колонну из ледяного эфира:

```java
package com.besson.tutorial.block;

import com.besson.tutorial.block.custom.PillarBlock;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.neoforged.neoforge.registries.DeferredBlock;

public class ModBlocks {
    // ... другие блоки ...

    // Колонна из ледяного эфира
    public static final DeferredBlock<PillarBlock> ICE_ETHER_PILLAR = registerBlock("ice_ether_pillar",
            () -> new PillarBlock(BlockBehaviour.Properties.of()
                    .strength(3.0f)
                    .sound(SoundType.STONE)
                    .noOcclusion() // Обязательно, так как модель имеет фигурные выступы
                    .requiresCorrectToolForDrops()
            ));
}
```

## 6. Настройка DataGen

### 6.1. BlockStates под 4 модели (`ModBlockStateProvider`)

Каждому значению `PillarType` соответствует своя 3D-модель (созданная в Blockbench или составленная из готовых элементов):
* `ice_ether_pillar_single.json`
* `ice_ether_pillar_bottom.json`
* `ice_ether_pillar_middle.json`
* `ice_ether_pillar_top.json`

Откройте `ModBlockStateProvider.java` и добавьте генератор состояний:

```java
package com.besson.tutorial.datagen;

import com.besson.tutorial.block.ModBlocks;
import com.besson.tutorial.block.custom.PillarBlock;
import com.besson.tutorial.block.custom.properties.PillarType;
import net.minecraft.world.level.block.Block;
import net.neoforged.neoforge.client.model.generators.BlockStateProvider;
import net.neoforged.neoforge.client.model.generators.ModelFile;

public class ModBlockStateProvider extends BlockStateProvider {

    @Override
    protected void registerStatesAndModels() {
        // ... другие блоки ...

        // Создаем генератор вариантов для колонны
        pillarBlock(ModBlocks.ICE_ETHER_PILLAR.get(), "ice_ether_pillar");
    }

    /**
     * Вспомогательный метод для генерации BlockState колонн
     */
    private void pillarBlock(Block block, String baseName) {
        ModelFile modelSingle = models().getExistingFile(modLoc("block/" + baseName + "_single"));
        ModelFile modelBottom = models().getExistingFile(modLoc("block/" + baseName + "_bottom"));
        ModelFile modelMiddle = models().getExistingFile(modLoc("block/" + baseName + "_middle"));
        ModelFile modelTop = models().getExistingFile(modLoc("block/" + baseName + "_top"));

        getVariantBuilder(block)
                .partialState().with(PillarBlock.TYPE, PillarType.SINGLE).modelForState().modelFile(modelSingle).addModel()
                .partialState().with(PillarBlock.TYPE, PillarType.BOTTOM).modelForState().modelFile(modelBottom).addModel()
                .partialState().with(PillarBlock.TYPE, PillarType.MIDDLE).modelForState().modelFile(modelMiddle).addModel()
                .partialState().with(PillarBlock.TYPE, PillarType.TOP).modelForState().modelFile(modelTop).addModel();

        // ⚠️ КРИТИЧЕСКИ ВАЖНО: Регистрация модели предмета в инвентаре!
        simpleBlockItem(block, modelSingle);
    }
}
```

### 6.2. Модель предмета в инвентаре: разбор ошибки
В видео автор обратил особое внимание на распространенную оплошность:
* Если объявить составной блок через `getVariantBuilder(...)`, но **забыть** вызвать `simpleBlockItem(block, modelSingle)`, игра сгенерирует blockstate для мира, но в инвентаре у предмета не будет модели (он отобразится как черно-фиолетовый куб отсутствующей текстуры).
* Строка `simpleBlockItem(block, modelSingle)` сообщает игре, что в руке и инвентаре блок всегда отображается как законченный одиночный объект `single`.

## 7. Тестирование в игре

1. Запустите генерацию данных через конфигурацию **`Run Data`**.  
   Убедитесь, что файл `blockstates/ice_ether_pillar.json` содержит все 4 варианта: `type=single`, `type=bottom`, `type=middle`, `type=top`.
2. Запустите клиент игры (**`Run Client`**).
3. Войдите в мир и возьмите колонну из инвентаря:
    * **Одиночный блок:** поставьте один блок на землю. Включите отладку `F3` — в свойствах справа отображается `type: single`. У колонны есть и основание, и верхняя капитель.
    * **Колонна из 2 блоков:** поставьте второй блок поверх первого:
        * Нижний блок мгновенно обновится на `type: bottom` (останется только база).
        * Верхний блок примет форму `type: top` (появится капитель).
    * **Высокая колонна (3+ блока):** продолжайте наращивать высоту:
        * Все промежуточные блоки автоматически станут `type: middle` (гладкие цилиндрические секции).
    * **Разрушение в середине:** сломайте средний блок в высокой колонне:
        * Блок под ним мгновенно превратится в верхушку `top`.
        * Блок над ним мгновенно превратится в основание `bottom`.
