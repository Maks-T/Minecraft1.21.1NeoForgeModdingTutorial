# Урок 32: Создание кастомных заборов и составных моделей Multipart в NeoForge 1.21.1

В Уроке 13 мы уже касались базовой регистрации забора через готовые ванильные методы. Однако если вы создаете уникальную кастомную 3D-модель в Blockbench (например, резную балюстраду, витой чугунный или ледяной забор), стандартные генераторы не подойдут.

В этом уроке мы детально изучим внутреннее устройство соединяемых блоков типа «Забор» (**Fence**):
* Разберем базовый класс **`CrossCollisionBlock`**: 4 горизонтальных направления (`NORTH`, `EAST`, `SOUTH`, `WEST`), центральный столб и расчет соединений.
* Раскроем главный секрет физики заборов: почему модель имеет высоту в 1 блок (`16px`), но игрок и мобы **не могут перепрыгнуть** через нее (хитбокс коллизии высотой 1.5 блока / `24px`).
* Освоим технологию **Multipart BlockState**: как собрать модель забора в мире из центрального столба и боковых перекладин прямо в DataGen.
* Применим оптимизацию вращения: вместо 4 разных моделей перекладин используем **одну** модель, поворачивая ее по оси Y на 0°, 90°, 180° и 270°.
* Реализуем механику привязывания животных поводком (**Lead / Tether**) и поддержку затопления водой (**Waterlogged**).

## 1. Теория: Архитектура заборов и Multipart-моделей

### 1.1. Класс `CrossCollisionBlock` и свойства направлений
Ванильный `FenceBlock` наследуется от базового класса `CrossCollisionBlock`. Этот класс управляет геометрией объектов, имеющих крестообразные ответвления в 4 стороны света:
* **`NORTH` (`BooleanProperty`):** соединение на север;
* **`EAST` (`BooleanProperty`):** соединение на восток;
* **`SOUTH` (`BooleanProperty`):** соединение на юг;
* **`WEST` (`BooleanProperty`):** соединение на запад;
* **`WATERLOGGED` (`BooleanProperty`):** находится ли блок под водой.

При размещении забора в мире метод `getStateForPlacement` опрашивает 4 соседних блока. Если соседний блок является забором или входит в тег `#minecraft:fences`, соответствующее булево свойство принимает значение `true`.

---

### 1.2. Физика 1.5 блока: `getCollisionShape` против `getShape`
В Minecraft обычный прыжок игрока без эффектов поднимает тело на **1.25 блока**.

Почему же забор нельзя перепрыгнуть, хотя визуально он выглядит как блок высотой в 1 куб?
* **Контур выделения (`getShape`):** имеет высоту ровно **16 пикселей (1.0 блок)**. Черная рамка при наведении курсора аккуратно очерчивает модель забора.
* **Физическая коллизия (`getCollisionShape`):** искусственно расширена вверх до **24 пикселей (1.5 блока)**! Твердое невидимое силовое поле не позволяет игроку и мобам запрыгнуть на забор без разгона на лошади или зелья прыгучести.

---

### 1.3. Принцип Multipart: модульная сборка блока на лету
Если бы забор описывался обычной системой вариантов `variants`, нам пришлось бы вручную создавать $2^4 = 16$ комбинаций моделей (забор без сторон, только на север, на север и восток, на север и юг и т.д.).

Вместо этого Minecraft использует систему **`multipart`**:
1. Всегда отрисовывается **Центральный столб (`post`)**.
2. Если `north=true` $\rightarrow$ поверх столба накладывается модель перекладины на север.
3. Если `east=true` $\rightarrow$ накладывается та же модель перекладины, но с поворотом `y=90`.
4. Если `south=true` $\rightarrow$ перекладина с поворотом `y=180`.
5. Если `west=true` $\rightarrow$ перекладина с поворотом `y=270`.

Благодаря этому для полноценного забора требуется нарисовать всего **две 3D-детали**: столб и одну перекладину!

---

### 1.4. Привязывание животных поводком
В коде Minecraft забор поддерживает взаимодействие с поводком (`LeadItem`):
* При клике ПКМ с поводком в руке животное привязывается к забору;
* В центре забора спавнится невидимая сущность узла поводка (`LeashFenceKnotEntity`);
* Повторный клик снимает поводок и возвращает его игроку.

## 2. Создание класса забора `ModFenceBlock`

В пакете `com.besson.tutorial.block.custom` создадим класс `ModFenceBlock.java`.

Мы унаследуем ванильный `FenceBlock`, сохранив все механики соединений, коллизии 1.5 блока и работы с поводком:

```java
package com.besson.tutorial.block.custom;

import net.minecraft.core.BlockPos;
import net.minecraft.core.Direction;
import net.minecraft.tags.BlockTags;
import net.minecraft.world.level.BlockGetter;
import net.minecraft.world.level.block.FenceBlock;
import net.minecraft.world.level.block.FenceGateBlock;
import net.minecraft.world.level.block.state.BlockState;

public class ModFenceBlock extends FenceBlock {

    public ModFenceBlock(Properties properties) {
        super(properties);
    }

    /**
     * Логика проверки: с какими блоками соединяется наш забор
     */
    @Override
    public boolean connectsTo(BlockState state, boolean isSideSolid, Direction direction) {
        // Забор соединяется с таким же забором нашего мода
        boolean isSameFence = state.is(this);
        
        // Либо с любыми ванильными заборами и калитками через теги
        boolean isOtherFence = state.is(BlockTags.FENCES) && state.is(BlockTags.WOODEN_FENCES) == this.defaultBlockState().is(BlockTags.WOODEN_FENCES);
        boolean isGate = state.getBlock() instanceof FenceGateBlock && FenceGateBlock.connectsToDirection(state, direction);

        return !isExceptionForConnection(state) && isSideSolid || isSameFence || isOtherFence || isGate;
    }
}
```

## 3. Регистрация забора в `ModBlocks`

Откройте `ModBlocks.java` и зарегистрируйте кастомный забор:

```java
package com.besson.tutorial.block;

import com.besson.tutorial.block.custom.ModFenceBlock;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.neoforged.neoforge.registries.DeferredBlock;

public class ModBlocks {
    // ... другие блоки ...

    // Кастомный забор из ледяного эфира
    public static final DeferredBlock<ModFenceBlock> ICE_ETHER_CUSTOM_FENCE = registerBlock("ice_ether_custom_fence",
            () -> new ModFenceBlock(BlockBehaviour.Properties.of()
                    .strength(2.0f, 3.0f)
                    .sound(SoundType.AMETHYST)
                    .noOcclusion() // Обязательно для заборов с прозрачными щелями
                    .requiresCorrectToolForDrops()
            ));
}
```

## 5. Настройка DataGen

### 5.1. Ручная сборка Multipart BlockState (`getMultipartBuilder`)

В Уроке 13 мы использовали метод `fenceBlock(...)`, который генерирует простую кубическую геометрию. Теперь мы напишем **полноценный модульный Multipart-билдер**, который умеет работать с любыми кастомными 3D-моделями из Blockbench!

Откройте `ModBlockStateProvider.java` в пакете `datagen`:

```java
package com.besson.tutorial.datagen;

import com.besson.tutorial.block.ModBlocks;
import com.besson.tutorial.block.custom.ModFenceBlock;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.FenceBlock;
import net.neoforged.neoforge.client.model.generators.BlockStateProvider;
import net.neoforged.neoforge.client.model.generators.ModelFile;

public class ModBlockStateProvider extends BlockStateProvider {

    @Override
    protected void registerStatesAndModels() {
        // ... другие блоки ...

        // Создаем составной BlockState для кастомного забора
        customFenceBlock(ModBlocks.ICE_ETHER_CUSTOM_FENCE.get(), "ice_ether_custom_fence");
    }

    /**
     * Модульный генератор забора через Multipart
     */
    private void customFenceBlock(Block block, String name) {
        // Загружаем модель центрального столба и одну базовую модель боковой перекладины
        ModelFile postModel = models().getExistingFile(modLoc("block/" + name + "_post"));
        ModelFile sideModel = models().getExistingFile(modLoc("block/" + name + "_side"));

        // 1. Сборка мира через MultipartBuilder
        getMultipartBuilder(block)
                // Центральный столб отображается ВСЕГДА
                .part().modelFile(postModel).add().end()

                // Северное соединение (без поворота Y)
                .part().modelFile(sideModel).add()
                .condition(FenceBlock.NORTH, true).end()

                // Восточное соединение (поворот на 90 градусов)
                .part().modelFile(sideModel).rotationY(90).add()
                .condition(FenceBlock.EAST, true).end()

                // Южное соединение (поворот на 180 градусов)
                .part().modelFile(sideModel).rotationY(180).add()
                .condition(FenceBlock.SOUTH, true).end()

                // Западное соединение (поворот на 270 градусов)
                .part().modelFile(sideModel).rotationY(270).add()
                .condition(FenceBlock.WEST, true).end();

        // 2. Генерация инвентарной модели для хотбара
        ModelFile inventoryModel = models().getExistingFile(modLoc("block/" + name + "_inventory"));
        simpleBlockItem(block, inventoryModel);
    }
}
```

> 💡 **Магия поворота `rotationY`:**  
> Обратите внимание на цепочку вызовов `.rotationY(...)`. Модель `_side` создается ориентированной строго на север. Движок игры сам повернет геометрию на восток, юг и запад, сэкономив ваше время на моделировании в Blockbench.

## 6. Тестирование в игре

1. Запустите генерацию данных через конфигурацию **`Run Data`**.  
   Загляните в сгенерированный файл `blockstates/ice_ether_custom_fence.json` — внутри будет структурированный блок `"multipart"` с 5 условиями!
2. Запустите клиент игры (**`Run Client`**).
3. Войдите в мир и возьмите забор из вкладки мода.
4. **Тест одиночного столба:**
    * Поставьте один забор на землю — отрисовывается красивый вертикальный центральный столб без боковых ответвлений.
5. **Тест соединений:**
    * Поставьте второй забор сбоку — между ними плавно вырастут перекладины.
    * Постройте угол, крестовину и Т-образный перекресток — система Multipart моментально включает нужные повороты на 90°, 180° и 270°.
    * Поставьте рядом калитку (`Fence Gate`) — забор образует плотное соединение с калиткой.
6. **Тест коллизии (1.5 блока):**
    * Подойдите к забору в режиме выживания и попытайтесь перепрыгнуть его — персонаж упрется в невидимую коллизию $24\text{px}$.
7. **Тест поводка:**
    * Возьмите ванильный поводок (`Lead`) и кликните ПКМ по овце, а затем по забору.
    * На столбе забора появится аккуратный узел из веревки, а животное окажется надежно привязано!
