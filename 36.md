# Урок 36: Естественная генерация деревьев в мире (Placed Features & Biome Modifiers) в NeoForge 1.21.1

В Уроке 35 мы создали основу нашего дерева из ледяного эфира: настроили саженец, написали логику роста `TreeGrower` и описали форму дерева в `ModConfiguredFeatures`. Однако сейчас получить это дерево можно только вручную — посадив саженец и вырастив его костной мукой. В дикой природе мира наше дерево пока не встречается.

В этом уроке мы завершим интеграцию дерева в игру и настроим его **естественную генерацию в биомах**:
* Разберем трёхзвенную архитектуру генерации мира в Minecraft: **`ConfiguredFeature` $\rightarrow$ `PlacedFeature` $\rightarrow$ `BiomeModifier`**.
* Изучим модификаторы размещения (**`PlacementModifier`**): как игра определяет количество деревьев на чанк (`countExtra`), высоту поверхности (`HEIGHTMAP`) и проверяет, приживется ли дерево на данном грунте.
* Создадим класс **`ModPlacedFeatures`** с использованием ванильного хелпера `VegetationPlacements.treePlacement(...)`.
* Познакомимся с мощным механизмом NeoForge — **`BiomeModifier`**: почему добавление растительности через модификаторы биомов не конфликтует с другими модами и не требует полной перезаписи ванильных биомов.
* Создадим класс **`ModBiomeModifiers`**, добавив генерацию деревьев эфира на равнины (`Plains`) и в леса (`Forest`).
* Обновим DataGen-провайдер **`ModDatapackEntries`**, сгенерируем новые JSON-файлы дата-паков и протестируем появление рощ в новом мире.

## 1. Теория: Архитектура генерации мира в 1.21+

### 1.1. Цепочка генерации: Configured $\rightarrow$ Placed $\rightarrow$ BiomeModifier
Генерация любого объекта в Minecraft (дерева, руды, цветка, структуры) разбита на три строго разделенных этапа:

```text
┌─────────────────────────────────┐
│   ConfiguredFeature (Урок 35)   │  "ЧТО генерировать?"
│   (Ствол, крона, блоки дуба)    │  Форма и материалы дерева.
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│   PlacedFeature (Этот урок)     │  "КАК и СКОЛЬКО размещать?"
│   (PlacementModifiers)          │  Количество на чанк, высота, фильтр блоков.
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│   BiomeModifier (Этот урок)     │  "ГДЕ размещать?"
│   (NeoForge Biome Modifiers)    │  Список биомов (равнины, леса, горы).
└─────────────────────────────────┘
```

---

### 1.2. Анатомия PlacedFeature и правила размещения
Объект `PlacedFeature` оборачивает созданный ранее `ConfiguredFeature` набором модификаторов (**`PlacementModifier`**):
* **Количество (`CountPlacement` / `countExtra`):** сколько попыток генерации предпринять в пределах одного чанка ($16 \times 16$ блоков).
* **Случайный разброс по горизонтали (`InSquarePlacement`):** распределяет точки спавна случайным образом по осям X и Z чанка.
* **Поиск поверхности (`HeightmapPlacement`):** проецирует генерацию на верхний твердый блок рельефа (`OCEAN_FLOOR` или `WORLD_SURFACE_WG`), чтобы деревья не появлялись под землей в пещерах или высоко в воздухе.
* **Фильтр выживания (`BlockPredicateFilter`):** проверяет, может ли саженец этого дерева стоять на блоке под ним (например, земля или дерн, но не камень или вода).
* **Фильтр биома (`BiomeFilter`):** гарантирует, что точка генерации не вылезла за границы целевого биома на стыке чанков.

Ванильный метод `VegetationPlacements.treePlacement(...)` собирает всю эту цепочку фильтров одной строкой кода.

---

### 1.3. Почему в NeoForge используются Biome Modifiers
В ванильном дата-паке Minecraft список генерации жестко прописан внутри JSON каждого конкретного биома (`data/minecraft/worldgen/biome/plains.json`).

> ⚠️ **Проблема совместимости модов:**  
> Если бы два разных мода попытались перезаписать файл `plains.json`, чтобы добавить свои деревья, победил бы только один мод (чья папка загрузилась позже), а деревья второго мода исчезли бы.

Для решения этой проблемы NeoForge разработал систему **`BiomeModifier`**:
* Моды не перезаписывают ванильные биомы целиком.
* Вместо этого мод регистрирует независимое правило: *«Добавь мое дерево на стадии декорации растительности во все биомы равнин и лесов»*.
* Игра динамически объединяет правила от десятков модов без конфликтов.

## 2. Создание класса `ModPlacedFeatures`

1. В пакете `com.besson.tutorial.worldgen` создайте класс `ModPlacedFeatures.java`.
2. Объявим ключ реестра `Registries.PLACED_FEATURE` и напишем метод `bootstrap`:

```java
package com.besson.tutorial.worldgen;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.block.ModBlocks;
import net.minecraft.core.Holder;
import net.minecraft.core.HolderGetter;
import net.minecraft.core.registries.Registries;
import net.minecraft.data.worldgen.BootstrapContext;
import net.minecraft.data.worldgen.placement.PlacementUtils;
import net.minecraft.data.worldgen.placement.VegetationPlacements;
import net.minecraft.resources.ResourceKey;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.level.levelgen.feature.ConfiguredFeature;
import net.minecraft.world.level.levelgen.placement.PlacedFeature;
import net.minecraft.world.level.levelgen.placement.PlacementModifier;

import java.util.List;

public class ModPlacedFeatures {

    // 1. Создаем ключ PlacedFeature для нашего дерева
    public static final ResourceKey<PlacedFeature> ICE_ETHER_TREE_PLACED_KEY =
            registerKey("ice_ether_tree_placed");

    /**
     * Наполнение реестра PlacedFeature
     */
    public static void bootstrap(BootstrapContext<PlacedFeature> context) {
        // Получаем доступ к реестру ConfiguredFeature, чтобы взять наше дерево из Урока 35
        HolderGetter<ConfiguredFeature<?, ?>> configuredFeatures = 
                context.lookup(Registries.CONFIGURED_FEATURE);

        // Получаем ссылку на ICE_ETHER_TREE_KEY
        Holder<ConfiguredFeature<?, ?>> treeConfiguredHolder = 
                configuredFeatures.getOrThrow(ModConfiguredFeatures.ICE_ETHER_TREE_KEY);

        // Регистрируем размещение дерева:
        register(context, ICE_ETHER_TREE_PLACED_KEY, treeConfiguredHolder,
                VegetationPlacements.treePlacement(
                        // 2 дерева гарантированно + шанс 10% (0.1f) на еще 1 дерево на чанк
                        PlacementUtils.countExtra(2, 0.1f, 1),
                        // Саженец для проверки условий выживания на грунте
                        ModBlocks.ICE_ETHER_SAPLING.get()
                ));
    }

    public static ResourceKey<PlacedFeature> registerKey(String name) {
        return ResourceKey.create(Registries.PLACED_FEATURE, 
                ResourceLocation.fromNamespaceAndPath(TutorialMod.MOD_ID, name));
    }

    private static void register(BootstrapContext<PlacedFeature> context,
                                 ResourceKey<PlacedFeature> key,
                                 Holder<ConfiguredFeature<?, ?>> configuration,
                                 List<PlacementModifier> modifiers) {
        context.register(key, new PlacedFeature(configuration, List.copyOf(modifiers)));
    }
}
```

### 2.2. Как работает `PlacementUtils.countExtra(count, extraChance, extraCount)`
* `count = 2`: базовое количество деревьев на чанк (всегда минимум 2 попытки);
* `extraChance = 0.1f`: шанс 10% на появление дополнительных деревьев;
* `extraCount = 1`: количество дополнительных деревьев при успешном шансе.

Если вы хотите сделать дерево редким (например, 1 дерево на 10 чанков), вместо `countExtra` используется `RarityFilter.onAverageOnceEvery(10)`.

## 3. Создание класса `ModBiomeModifiers`

Теперь укажем, в каких именно биомах мира должны появляться наши размещенные деревья.

1. В пакете `worldgen` создайте класс `ModBiomeModifiers.java`.
2. Используем реестр `NeoForgeRegistries.Keys.BIOME_MODIFIERS`:

```java
package com.besson.tutorial.worldgen;

import com.besson.tutorial.TutorialMod;
import net.minecraft.core.HolderGetter;
import net.minecraft.core.HolderSet;
import net.minecraft.core.registries.Registries;
import net.minecraft.data.worldgen.BootstrapContext;
import net.minecraft.resources.ResourceKey;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.level.biome.Biome;
import net.minecraft.world.level.biome.Biomes;
import net.minecraft.world.level.levelgen.GenerationStep;
import net.minecraft.world.level.levelgen.placement.PlacedFeature;
import net.neoforged.neoforge.common.world.BiomeModifier;
import net.neoforged.neoforge.common.world.BiomeModifiers;
import net.neoforged.neoforge.registries.NeoForgeRegistries;

public class ModBiomeModifiers {

    // 1. Создаем ключ модификатора биомов для добавления деревьев
    public static final ResourceKey<BiomeModifier> ADD_ICE_ETHER_TREE =
            registerKey("add_ice_ether_tree");

    /**
     * Наполнение реестра BiomeModifier
     */
    public static void bootstrap(BootstrapContext<BiomeModifier> context) {
        // Доступ к реестру размещенных фич (PlacedFeature)
        HolderGetter<PlacedFeature> placedFeatures = context.lookup(Registries.PLACED_FEATURE);
        // Доступ к реестру биомов
        HolderGetter<Biome> biomes = context.lookup(Registries.BIOME);

        // Регистрируем модификатор:
        context.register(ADD_ICE_ETHER_TREE, new BiomeModifiers.AddFeaturesBiomeModifier(
                // Список биомов, куда добавляем дерево (Равнины и обычный Лес)
                HolderSet.direct(biomes.getOrThrow(Biomes.PLAINS), biomes.getOrThrow(Biomes.FOREST)),
                // Ссылка на наш PlacedFeature
                HolderSet.direct(placedFeatures.getOrThrow(ModPlacedFeatures.ICE_ETHER_TREE_PLACED_KEY)),
                // Шаг генерации: растительность
                GenerationStep.Decoration.VEGETAL_DECORATION
        ));
    }

    public static ResourceKey<BiomeModifier> registerKey(String name) {
        return ResourceKey.create(NeoForgeRegistries.Keys.BIOME_MODIFIERS, 
                ResourceLocation.fromNamespaceAndPath(TutorialMod.MOD_ID, name));
    }
}
```

### 3.1. Шаги декорации (`GenerationStep.Decoration`)
Minecraft генерирует мир послойно:
1. `RAW_GENERATION` — форма рельефа;
2. `LAKES` — озера;
3. `UNDERGROUND_ORES` — руды;
4. **`VEGETAL_DECORATION`** — трава, цветы, кактусы и **деревья**;
5. `TOP_LAYER_MODIFICATION` — снег и лед.

Деревья обязательно регистрируются на шаге `VEGETAL_DECORATION`.

## 4. Обновление DataGen (`ModDatapackEntries`)

Чтобы задача Gradle `runData` скомпилировала файлы для обоих новых реестров, добавим их в `RegistrySetBuilder`.

Откройте класс `ModDatapackEntries.java` (созданный в Уроке 35) в пакете `datagen` и дополните поле `BUILDER`:

```java
package com.besson.tutorial.datagen;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.worldgen.ModBiomeModifiers;
import com.besson.tutorial.worldgen.ModConfiguredFeatures;
import com.besson.tutorial.worldgen.ModPlacedFeatures;
import net.minecraft.core.HolderLookup;
import net.minecraft.core.RegistrySetBuilder;
import net.minecraft.core.registries.Registries;
import net.minecraft.data.PackOutput;
import net.neoforged.neoforge.common.data.DatapackBuiltinEntriesProvider;
import net.neoforged.neoforge.registries.NeoForgeRegistries;

import java.util.Set;
import java.util.concurrent.CompletableFuture;

public class ModDatapackEntries extends DatapackBuiltinEntriesProvider {

    // Добавляем PlacedFeature и BiomeModifier в строитель реестров
    public static final RegistrySetBuilder BUILDER = new RegistrySetBuilder()
            .add(Registries.CONFIGURED_FEATURE, ModConfiguredFeatures::bootstrap)
            .add(Registries.PLACED_FEATURE, ModPlacedFeatures::bootstrap)
            .add(NeoForgeRegistries.Keys.BIOME_MODIFIERS, ModBiomeModifiers::bootstrap);

    public ModDatapackEntries(PackOutput output, CompletableFuture<HolderLookup.Provider> registries) {
        super(output, registries, BUILDER, Set.of(TutorialMod.MOD_ID));
    }
}
```

1. Запустите конфигурацию запуска **`Run Data`** (или команду `./gradlew runData`).

3. Откройте директорию `src/generated/resources/` и проверьте появившиеся файлы:

## 6. Тестирование в игре

1. Запустите клиент игры (**`Run Client`**).
2. ⚠️ **Критически важно:** Создайте **новый мир** (в старых уже сгенерированных чанках новые деревья не появятся!).
3. Найдите биом **Равнины (Plains)** или **Лес (Forest)** (можно использовать команду телепортации `/locate biome plains`).
4. **Результат:**
    * Среди привычной зеленой травы и дубов появятся красивые деревья ледяного эфира с бирюзовой листвой и характерным темным стволом.
    * Деревья генерируются группами по 1–3 штуки на чанк, гармонично вписываясь в окружающий ландшафт.
    * Попробуйте сломать листву: с нее корректно выпадают саженцы `Ice Ether Sapling`, обеспечивая цикл возобновляемости ресурсов в режиме выживания!

## 7. Частые ошибки

* **Деревья не появляются в мире:** вы загрузили старый мир, в котором чанки уже были сгенерированы до добавления мода. Создайте новый мир.
* **Ошибка `NullPointerException` при запуске `runData`:** в `ModPlacedFeatures` ключ `ICE_ETHER_TREE_KEY` вызван до того, как был инициализирован класс `ModConfiguredFeatures` (проверьте правильность импортов и имен ключей).
* **Игра падает при создании мира (`Registry lookup failed`):** забыли добавить `.add(Registries.PLACED_FEATURE, ...)` или `.add(NeoForgeRegistries.Keys.BIOME_MODIFIERS, ...)` в `ModDatapackEntries.BUILDER`.
* **Деревья висят в воздухе или прорастают в пещерах:** в списке модификаторов размещения пропущен `PlacementUtils.HEIGHTMAP_OCEAN_FLOOR` (присутствующий внутри фабрики `VegetationPlacements.treePlacement`).
