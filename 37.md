# Урок 37: Создание цветов и цветочных горшков (FlowerBlock & FlowerPotBlock) в NeoForge 1.21.1

В Уроках 35 и 36 мы разобрали создание и генерацию деревьев. Теперь мы продолжим тему флоры Minecraft и создадим **собственный цветок — Цветок ледяного эфира (`Ice Ether Flower`)**, а также соответствующий **декоративный цветочный горшок (`Potted Flower`)**.

В этом уроке мы разберем:
* Как устроен класс **`FlowerBlock`**: почему каждый ванильный цветок обязан хранить эффект зелья для механики подозрительного рагу (*Suspicious Stew*).
* Главный секрет естественного вида растений в Minecraft: что такое **`BlockBehaviour.OffsetType.XZ`** и почему цветы на поляне никогда не стоят строго по центру блока.
* Почему для цветка в горшке регистрируется **отдельный блок (`FlowerPotBlock`) без собственного предмета** (`BlockItem`), и как работает связка с пустым ванильным горшком через метод **`addPlant(...)`** в событии `FMLCommonSetupEvent`.
* Настройку DataGen: создание крестообразной модели **`cross`**, модели горшка **`flower_pot_cross`** со слоем прозрачности **`cutout`** и специфической таблицы лута (`createPotFlowerItemTable`).

## 1. Теория: Архитектура цветов и горшков в Minecraft

### 1.1. Класс `FlowerBlock` и эффект подозрительного рагу
Все небольшие цветы в Minecraft наследуются от класса `FlowerBlock` (который, в свою очередь, расширяет `BushBlock`).

Конструктор `FlowerBlock` принимает:
```java
new FlowerBlock(Holder<MobEffect> suspiciousStewEffect, float effectDuration, Properties properties)
```
1. **`suspiciousStewEffect`**: статус-эффект зелья, который получит игрок, если сварит этот цветок в крафте **Подозрительного рагу** (миска + красный гриб + коричневый гриб + цветок). Например, одуванчик дает насыщение, а василек — прыгучесть. Мы зададим эффект *Ночного зрения* (`MobEffects.NIGHT_VISION`).
2. **`effectDuration`**: длительность накладываемого эффекта в секундах (например, `5.0f`).
3. **`properties`**: физические параметры блока.

---

### 1.2. Случайное смещение по осям XZ (`OffsetType.XZ`)
Если бы цветы располагались строго в центре своего блока $(X = 0.5, Z = 0.5)$, любая цветочная поляна выглядела бы искусственной и неестественно ровной, как шахматная доска.

Чтобы избежать этого, в Minecraft используется свойство:
```java
.offsetType(BlockBehaviour.OffsetType.XZ)
```
Движок игры на основе координат блока вычисляет псевдослучайный сдвиг стебля по горизонтальным осям X и Z. В результате каждый цветок на поляне стоит с небольшим индивидуальным смещением, создавая эффект живой дикой природы.

---

### 1.3. Почему горшок — это отдельный блок без `BlockItem`
В ванильном Minecraft игрок держит в руках только **пустой цветочный горшок** (`Items.FLOWER_POT`) и **сам цветок** (`ICE_ETHER_FLOWER`). В инвентаре не существует предмета «Цветок в горшке».

Механика работает следующим образом:
1. Игрок ставит пустой блок горшка (`Blocks.FLOWER_POT`).
2. Кликает по нему ПКМ с цветком в руке.
3. Игра удаляет один цветок из руки и заменяет пустой горшок на отдельный блок **`POTTED_ICE_ETHER_FLOWER`** (`FlowerPotBlock`).
4. При разрушении такого горшка выпадают сразу **два** предмета: пустой горшок и цветок.

Поэтому блок горшка с цветком регистрируется **без `BlockItem`**, напрямую через `BLOCKS.register(...)`.

## 2. Регистрация цветка и горшка в `ModBlocks`

Откройте класс `ModBlocks.java` и добавьте регистрацию цветка и горшка:

```java
package com.besson.tutorial.block;

import com.besson.tutorial.TutorialMod;
import com.besson.tutorial.item.ModItems;
import net.minecraft.world.effect.MobEffects;
import net.minecraft.world.item.BlockItem;
import net.minecraft.world.item.Item;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.Blocks;
import net.minecraft.world.level.block.FlowerBlock;
import net.minecraft.world.level.block.FlowerPotBlock;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.neoforged.neoforge.registries.DeferredBlock;
import net.neoforged.neoforge.registries.DeferredRegister;

import java.util.function.Supplier;

public class ModBlocks {
    public static final DeferredRegister.Blocks BLOCKS = 
            DeferredRegister.createBlocks(TutorialMod.MOD_ID);

    // ... другие блоки ...

    // ================= ЦВЕТЫ И ГОРШКИ =================

    // 1. Цветок ледяного эфира (дает Ночное зрение на 5 секунд в подозрительном рагу)
    public static final DeferredBlock<FlowerBlock> ICE_ETHER_FLOWER = registerBlock(
            "ice_ether_flower",
            () -> new FlowerBlock(
                    MobEffects.NIGHT_VISION,
                    5.0f,
                    BlockBehaviour.Properties.ofFullCopy(Blocks.DANDELION)
                            .noCollission()
                            .instabreak()
                            .sound(SoundType.GRASS)
                            .offsetType(BlockBehaviour.OffsetType.XZ) // Случайный сдвиг на поляне!
            )
    );

    // 2. Цветочный горшок с цветком (РЕГИСТРИРУЕТСЯ БЕЗ BlockItem!)
    public static final DeferredBlock<FlowerPotBlock> POTTED_ICE_ETHER_FLOWER = BLOCKS.register(
            "potted_ice_ether_flower",
            () -> new FlowerPotBlock(
                    () -> (FlowerPotBlock) Blocks.FLOWER_POT, // Ссылка на пустой ванильный горшок
                    ICE_ETHER_FLOWER,                          // Ссылка на размещаемый цветок
                    BlockBehaviour.Properties.ofFullCopy(Blocks.POTTED_DANDELION)
            )
    );

    // Вспомогательные методы регистрации обычных блоков с предметами...
    private static <T extends Block> DeferredBlock<T> registerBlock(String name, Supplier<T> blockSupplier) {
        DeferredBlock<T> registeredBlock = BLOCKS.register(name, blockSupplier);
        registerBlockItem(name, registeredBlock);
        return registeredBlock;
    }

    private static <T extends Block> void registerBlockItem(String name, DeferredBlock<T> block) {
        ModItems.ITEMS.register(name, () -> new BlockItem(block.get(), new Item.Properties()));
    }
}
```

## 3. Связка с ванильным цветочным горшком (`FMLCommonSetupEvent`)

Чтобы игра знала, что при клике нашим цветком по ванильному пустому горшку его нужно превратить в `POTTED_ICE_ETHER_FLOWER`, зарегистрируем связь в методе `addPlant(...)`.

Откройте ваш главный класс мода (`TutorialMod.java`) или класс общих событий и подпишитесь на `FMLCommonSetupEvent`:

```java
package com.besson.tutorial;

import com.besson.tutorial.block.ModBlocks;
import net.minecraft.world.level.block.Blocks;
import net.minecraft.world.level.block.FlowerPotBlock;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.common.Mod;
import net.neoforged.fml.event.lifecycle.FMLCommonSetupEvent;

@Mod(TutorialMod.MOD_ID)
public class TutorialMod {

    public TutorialMod(IEventBus modEventBus) {
        // Регистрация реестров...
        ModBlocks.register(modEventBus);
        // ...

        // Регистрируем слушатель общего сетапа мода
        modEventBus.addListener(this::commonSetup);
    }

    private void commonSetup(final FMLCommonSetupEvent event) {
        event.enqueueWork(() -> {
            // Связываем ванильный горшок с нашим цветком и блоком горшка
            ((FlowerPotBlock) Blocks.FLOWER_POT).addPlant(
                    ModBlocks.ICE_ETHER_FLOWER.getId(),
                    ModBlocks.POTTED_ICE_ETHER_FLOWER
            );
        });
    }
}
```

## 5. Настройка генерации данных (DataGen)

### 5.1. Таблицы лута (`createPotFlowerItemTable`)
* Сам цветок при разрушении сбрасывает себя (`dropSelf`).
* Горшок с цветком при разрушении должен сбрасывать **два предмета**: пустой ванильный горшок (`Blocks.FLOWER_POT`) и наш цветок. Для этого в `BlockLootSubProvider` есть готовый метод `createPotFlowerItemTable(...)`.

Откройте `ModBlockLootTablesProvider.java`:

```java
@Override
protected void generate() {
    // ... другие блоки ...

    // Дроп обычного цветка
    dropSelf(ModBlocks.ICE_ETHER_FLOWER.get());

    // Дроп горшка с цветком (выпадает пустой горшок + сам цветок)
    add(ModBlocks.POTTED_ICE_ETHER_FLOWER.get(), block -> 
            createPotFlowerItemTable(ModBlocks.ICE_ETHER_FLOWER.get()));
}
```

---

### 5.2. BlockStates и 3D-модели (`cross` и `flower_pot_cross`)
* Для цветка создается крестообразная модель `cross` со слоем `cutout`.
* Для горшка с цветком используется ванильный родитель `minecraft:block/flower_pot_cross`, где в слот `"plant"` подставляется текстура нашего цветка.

Откройте `ModBlockStateProvider.java` в пакете `datagen`:

```java
@Override
protected void registerStatesAndModels() {
    // ... другие блоки ...

    // 1. Модель и BlockState цветка
    simpleBlock(ModBlocks.ICE_ETHER_FLOWER.get(), 
            models().cross(ModBlocks.ICE_ETHER_FLOWER.getId().getPath(), 
                    modLoc("block/ice_ether_flower")).renderType("cutout"));

    // 2. Модель и BlockState цветка в горшке
    simpleBlock(ModBlocks.POTTED_ICE_ETHER_FLOWER.get(), 
            models().singleTexture(ModBlocks.POTTED_ICE_ETHER_FLOWER.getId().getPath(), 
                    mcLoc("block/flower_pot_cross"), 
                    "plant", 
                    modLoc("block/ice_ether_flower")).renderType("cutout"));
}
```

### 5.4. Ванильные теги цветов
Чтобы пчелы опыляли наш цветок, кролики могли его есть, а рецепты красителей и механики костной муки распознавали его, добавим цветок в ванильные теги:

В `ModBlockTagsProvider.java`:
```java
tag(BlockTags.FLOWERS).add(ModBlocks.ICE_ETHER_FLOWER.get());
tag(BlockTags.SMALL_FLOWERS).add(ModBlocks.ICE_ETHER_FLOWER.get());
```

В `ModItemTagsProvider.java`:
```java
tag(ItemTags.FLOWERS).add(ModBlocks.ICE_ETHER_FLOWER.asItem());
tag(ItemTags.SMALL_FLOWERS).add(ModBlocks.ICE_ETHER_FLOWER.asItem());
```

## 6. Тестирование в игре

1. Запустите конфигурацию **`Run Data`** — сгенерируются модели цветка, горшка, таблицы лута и теги.
2. Запустите клиент игры (**`Run Client`**).
3. Войдите в мир и возьмите из инвентаря **Цветок ледяного эфира (`Ice Ether Flower`)** и ванильный **Цветочный горшок (`Flower Pot`)**.
4. **Тест посадки на поляне:**
    * Посадите несколько цветков подряд на блоки травы:
    * Обратите внимание: цветы не стоят по строгой сетке, а слегка сдвинуты в разные стороны благодаря `OffsetType.XZ`.
    * Текстура прозрачна по краям, без черного фона (благодаря слою `cutout`).
5. **Тест цветочного горшка:**
    * Установите пустой глиняный горшок на землю.
    * Кликните по нему ПКМ с цветком в руке — цветок из руки исчезнет, а внутри горшка появится аккуратный миниатюрный росток!
6. **Тест разрушения горшка:**
    * Переключитесь в режим выживания (`/gamemode survival`) и сломайте горшок с цветком рукой или инструментом:
    * На землю выпадут сразу **два предмета**: целый пустой цветочный горшок и цветок ледяного эфира.

## 7. Частые ошибки

* **При клике цветком по горшку ничего не происходит:** забыли добавить вызов `((FlowerPotBlock) Blocks.FLOWER_POT).addPlant(...)` внутри `FMLCommonSetupEvent`.
* **В инвентаре или в мире отображается черно-фиолетовый куб горшка:** в `ModBlockStateProvider` неправильно указан родительский путь к ванильной модели (нужно использовать `mcLoc("block/flower_pot_cross")`).
* **Цветок в мире окружен черной непрозрачной рамкой:** пропущен вызов `.renderType("cutout")` при генерации моделей в DataGen.
* **Игра падает при старте с ошибкой регистрации предметов:** для `POTTED_ICE_ETHER_FLOWER` был ошибочно вызван метод `registerBlock`, создавший `BlockItem`. Горшки с цветами должны регистрироваться через прямой `BLOCKS.register(...)`.
